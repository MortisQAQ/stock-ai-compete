### 3.3 slides 独有能力（相对其它 deck 方案）

| 能力 | 说明 |
|---|---|
| **Reveals / fragments** | 内容按点击逐条出现；Next 会走完最后一页的每个 reveal 才消失 |

| **Presenter mode** | 观众看干净全屏；演讲者看到当前页 + 备注 + 下一页 + 计时器 |

配套 agent skills：

- `motion-doctrine`（**核心**，见 3.4）
- `cut-the-curve`（转场曲线全目录，含 waterfall entry + nudge curve）
- `seam-craft`（接缝工艺）
- `oversized-cursor`（超大光标叙事）
- `captions-overlay` / `changelog-video`
- `registry/blocks/`：glass-shard-title / wireframe-portal-title / cuboid-carousel / orbit-card / frost-sequence-camera-orbit / code-slice-hero / canopy-part-title
- `skills/`：hyperframes / hyperframes-cli / hyperframes-registry / figma / media-use / remotion-to-hyperframes

### 3.4 motion-doctrine —— 真正的宝藏

> The high-level motion law that makes a multi-scene video feel like **ONE continuous camera move** instead of a stack of independently-animated slides.

涵盖：vector law（怎么出场决定怎么入场，含 Z 轴 scale-sign 规则）、film current、carrier elements、causal motion、**Seam Gate**（构建门禁式强制）、禁止 idle wobble（运动必须表演，不能只是呼吸）、stillness-before-climax。

**对我们最有用的一点**：它管的正是**页与页之间的接缝**——这是所有 ppt skill 都缺的一环。哪怕不做视频，这套法则也能直接约束 deck 的页面转场。

### 3.5 三个硬伤（必须写清）

1. **没有 PPTX 导出。** 遍历整个仓库树，`export` 相关路径只有 video / render / share，**不存在任何 pptx / powerpoint 代码路径**。汇报交付需要 PPTX 时它不能用。
2. **deck 渲染 MP4 会静默失败。** 官方 Warning 原文：

   > Do not run `hyperframes render` on a deck. It does not fail — a deck has no master root composition, so the render resolves only the **first** slide and writes a silently truncated MP4.

3. **是重体系。** `npx hyperframes` CLI + studio + lint + check，整套为视频管线设计。只做 deck 属于开卡车买菜。

### 3.6 本项目的用法

- **当前阶段：不用。** PPT 交付用 guizang / open-slide 更轻。
- **后续视频阶段：主引擎。** 78.5K 星 + 100+ 提交/月 + Apache-2.0，是整个生态里最活跃、最可押注的。
- **现在就可以抄的**：`motion-doctrine` 的 Seam Gate 与 vector law，作为 deck 页面转场的设计约束。

### 4.5 为什么 Data Storytelling 对 stock-ai-compete 特别对口

实际拉取 `styles/dataviz/STYLE.md` 摘要：

> **The chart is the film.** 每个 mark 都是真实数字，每次运动都是有意义的图表操作（一个点落地、一条轴生长、标度切换、系列 morph、一条手写批注钉上去）。数据真实、开源、可溯源。**你只改变取景，永远不改数字。**
>
> 附图表选型矩阵：比较类别/排名 → 条形或条形竞速；两个量的关系 → 散点/气泡；地点 → 地图；部分与整体 → 华夫图；前 → 后 → 斜率图/哑铃图；分布 → 直方图/蜂群图；流向 → 桑基；时间变化 → 线/点系列/条纹/面积。
>
> 三层构成故事而非信息图：**人的尺度**（手写批注钉在数据点上）、**表演者**（一支实体铅笔逐笔绘制）、**可听化**（每个 mark 是一个音高，趋势先被听见再被读到）。
>
> 明确划线：**不是 dashboard**（一次一个想法）、**不是带图表的 keynote**（没有幻灯片）、永不装饰。
>
> 参考（仅取语法，不抄图表/版式/字体，且片中不得点名）：Hans Rosling *200 Countries, 200 Years, 4 Minutes*、Ed Hawkins 暖化条纹、The Pudding / NYT scrollytelling。

**净值曲线、回撤、夏普、持仓权重这几页，命中率极高。**

### 4.6 必须承认的边界

> README 首屏警告原文：**Built for Claude.** The styles are tuned for Claude Opus 5.5; other models may not reproduce them well, so use them with care.

- 本会话当前模型为 `deepseek-v4.1-flash`，**风格复现率要打问号**
- 但 `STYLE.md` 作为**规格文档**阅读是安全的（它描述视觉结果，不是执行指令）
- 稳妥用法：**读规格 → 自己实现**，而非指望 skill 自动复现

## 6. 从 PPT 到视频的迁移路径（预留）

当前只做 presentation，但结构性预留：

    风格语汇   lemo-opuscar 的 styles/<x>/STYLE.md  →  直接读，改写为 deck 版规范
    运动法则   HyperFrames 的 motion-doctrine       →  Seam Gate / vector law 约束页面转场
    出稿        guizang-ppt-skill                   →  单文件 HTML deck
    交付升级    open-slide                          →  PPTX / PDF
    视频阶段    HyperFrames                         →  HTML → MP4（注意：deck 本身不可 render）

**关键交接点**：deck 与视频**不共用同一份源码**。HyperFrames 的 deck 没有 master root composition，所以 deck 版与视频版必须是两个项目，只共享 `STYLE.md` 与 `motion-doctrine` 这两层「知识」，不共享渲染产物。
