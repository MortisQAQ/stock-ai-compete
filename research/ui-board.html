同行的界面，
与我们要补的那一半。

四家真实产品的界面实拍（不看宣传稿），与 openOutcry 当前原型同口径比对：同为 1440 宽桌面、同为"把一次运行讲清楚"这个任务。结论不是"换风格"，而是"补数据层"。任意截图可点击放大，滚轮自由缩放。

⌕ 点击截图可放大 · 滚轮缩放

我们不缺设计感，缺"仪器感"。现有原型是漂亮的浅色编辑式版面，但它看起来像"产品文档的网页版"，而不是"一台跑和测 Agent 的设施"。
同赛道对手在信息密度、数据可视化、可审计性上全面压过我们；而我们在人机协同、证据编号、接入向导上又明显领先。
因此方向是 浅纸骨架 + 深色数据层 的混合体——叙事用浅色（投影、打印友好），数字、图表、台账、原始 JSON 用深色等宽块。这个位置，TraderHarness（全暗）和 TradingAgents-CN（全亮 Streamlit）都没占。

06

TraderHarness 架构速读

从代码与依赖文件读出来的，不看宣传稿
层他们的做法（已核对仓库）对我们的启示
引擎 纯 Python 包 traderharness（PyPI，≥3.10）；core/ 下 engine / env / events / portfolio / calendar / budget / runner 各自成文件，依赖只有 pandas / numpy / httpx / pyarrow 先定死 core 的六件事：模拟时钟、观测、账户、撮合、事件、预算。不要一开始就碰界面
抗污染 masking.py / entity_masking.py / leakage.py 三个独立模块，而非一个开关函数 我们文档里的"五开关"应一开关一模块，能单独写单测、单独做 A/B
服务 FastAPI + uvicorn（server/app.py），外加 run_manager 与 paper_manager 两个生命周期管理器 运行生命周期 ≠ 模拟盘会话，两者要分开管理；前端只订阅事件流
前端 React 19 + Vite + React Router + lucide-react；webui/e2e 用 Playwright 端到端 原型阶段保持单文件没问题；开发期必须换成 Vite + 组件化，否则图表和表格会失控
回放 轨迹是 .jsonl，且把 demo 回放（momentum_dragon_2024-03-14.jsonl）打进 wheel 随包分发，做到"零凭据三步体验" 把我们的"可回放"尽快定成 jsonl 事件格式，并内置一条样例轨迹用于汇报现场演示
数据 可选依赖里是 baostock / mootdx / duckdb；README 称覆盖五年全市场日线与 5 分钟线 强信号：A 股历史行情用免费源可行 → 我们的"数据可行性"风险应下调，真正要验证的是历史新闻/公告的时点快照
交付 PyPI 包 + mkdocs 文档站 + CI + Dockerfile + CHANGELOG，版本 1.1.0（Research Beta） 期末至少要有"可 pip 安装 + 一条命令跑起来"的形态，文档站比 Word 更有说服力

一个必须正视的事实：它已经跑过 21 个交易日的魔鬼窗口基准，拿出四个模型的区间收益、夏普、回撤、胜率对照表。这类"可复现的小基准"正是期中之后我们必须补的东西——比再多三页产品文档都更能证明系统真的存在。
