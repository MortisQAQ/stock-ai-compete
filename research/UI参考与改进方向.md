# openOutcry UI 参照调研与改造方向

> 调研时间：2026-10-28　｜　口径：1440 桌面宽、真实截图，不看宣传稿
> 参照物截图存放：`research/ui-refs/`
> 可视化看板：`research/ui-board.html`（每张截图可点击放大，支持滚轮自由缩放、拖拽平移、←/→ 切换，长图自动按宽度铺满）

---

## 0. 结论先说

我们**不缺设计感，缺的是"仪器感"**。

现有原型是漂亮的浅色编辑式版面——衬线品牌、纸感底色、卡片留白——但它传达的身份是"一份产品文档的网页版"，而不是"一台用来跑和测 Agent 的设施"。同期同类产品（TraderHarness、PanWatch、QuantConnect）在**信息密度、数据可视化、可审计性**上全面压过我们一个量级；而它们在**人机协同、证据编号、接入向导**上又明显不如我们。

所以改造方向不是"换成暗色终端"，而是做一个**"浅色纸感骨架 + 深色数据层"的混合体**：叙事和流程用浅纸（投影、打印、汇报都友好），数字、图表、台账、原始 JSON 用深色等宽块。这个组合既能保住我们唯一的视觉身份，又补上"仪器感"，而且恰好是 TraderHarness（全暗）和 TradingAgents-CN（全亮 Streamlit）都没占的位置。

## 2. 逐家拆解

### 2.1 TraderHarness —— 最该学的对手

**它做对的（值得直接搬）**

1. **事件台账，不是聊天记录。** 右侧"决策事件流"每条带序号（#5998）、时间、类型 chip（全部/阶段/工具/订单/错误/思考）、智能体筛选、自动滚动开关。同样的事件，它读起来像银行流水，我们读起来像微信。
2. **运行上下文常驻页头。** 右上角一个下拉就是"当前运行 ba685837 · 已完成 · 4 个智能体"，旁边是"查看研究档案"。用户永远不会忘记自己在看哪次运行。
3. **状态条诚实到刺眼。** 页头写着"系统就绪 · 严格时点追溯"；逐笔复盘页直接写"当前工作仅保存了可见回复与下单理由；系统不会伪造缺失的隐藏推理"。**把我们文档第三、七节的诚信承诺，直接翻译成了界面元素。**
4. **对比页是独立一级页面。** 多智能体权益曲线叠加 + 横向排名表（累计收益 / 相对沪深 300 / 夏普 / 最大回撤 / 胜率 / 成交次数）。我们文档里"复制配置重跑并比较"，在 UI 里根本不存在。
5. **逐笔复盘三段式。** 左侧成交流水（600608 买入/卖出带日期与阶段）→ 中上 K 线 → 中下"决策链"三条理由 → 右侧"执行证据"原始 JSON（action/price/quantity/net_income/portfolio_after）。这是"可追溯"这个词最具体的形态。
6. **图表三件套**：权益曲线与基准对比、水下回撤曲线、工具使用情况横向条形（190/137/128…调用次数）。

**它的代价（不要抄）**

- **像素办公室占了整屏主视觉。** 好看、有传播性，但在"评测设施"里它不是证据，只是氛围。我们如果做，最多做成可开关的彩蛋。
- 全局近黑 + 低对比灰，长时间读表格疲劳；投影到教室会糊成一片。
- 承载的是"多个智能体并排跑"，与我们的"单次运行 + 人机协同审批"不是一回事。

### 2.2 PanWatch —— 密度与习惯

**它做对的**

1. **一屏 6 个 KPI**：总市值 / 总盈亏 / 今日盈亏 / 可用资金 / 总资产 / 仓位占比。标签极小、数字极大。
2. **高密度持仓表**：股票｜现价｜涨跌｜成本｜持仓｜市值｜盈亏｜今日｜风格｜Agent｜操作，行内用 chip 标"持有/减仓/卖出"，行下小字标来源与时间（`来源: TradingAgents 深度 · 21:08（已过期）`）。**"数据来源 + 是否过期"直接写在行里，这个我们要学。**
3. **模拟盘页结构**：KPI 条 → 收益曲线 → 策略绩效表（策略/已平仓/胜率/已实现盈亏/平均盈亏%/平均持仓天数）。
4. **红涨绿跌。** ← 见下文第 3.1 节，这是我们当前的硬伤。

**它的代价**：密到没有呼吸感，无层级、无主次，新用户找不到入口。

### 2.3 TradingAgents-CN —— 反面教材，但有可取处

- 整个界面是 Streamlit 默认样式 + emoji 当图标（📊 🧠 ⚖️ 🚀），亮底大字号堆叠，右侧 tab 切"市场技术分析 / 基本面分析 / 新闻事件分析 / 风险评估 / 投资建议 / 研究团队决策"。
- **本质是"一次提问生成一份报告"，没有运行 ID、没有事件流、没有账户、没有回放。** 它反证了我们的差异化确实存在。
- 可取的一点：**按角色分 tab 组织长报告**，长文本不会糊成一坨。我们的"决策档案"页可以借这个结构。

### 2.4 QuantConnect —— 回测报告的标准答案

1. **KPI 条 + 三层图垂直堆叠**：净值（含每日表现柱状副图）→ 回撤曲线 → 资产暴露/排名侧栏。信息密度极高但层次清晰。
2. **把"过拟合风险"做成了界面徽章**：右侧 Research Guide 明写"99 Backtests Remaining → Likely Not Overfit"、"3 Parameters Detected → Likely Not Overfit"。侧栏还有 `PSR 9.6%  Rank 17` 进度条。
   → **这是我们"抗污染五开关 + DSR + 最小样本门槛"最该落地的形态：不是写在方法论章节里，而是常驻在运行页和结果页上。**
3. **Results 列表每次回测一行**，列是 PSR / Sharpe / Trades / 时间——"每次运行都是可比较记录"这个产品承诺，在 UI 层就是一张表。
4. 代价：无圆角、细线框、2008 年报表审美，可读但陈旧。

## 2.5 TraderHarness 架构速读（从代码读，不看宣传稿）

这一节是从仓库本身读出来的，不是从首页摘的。它的成熟度比界面给人的印象更高：PyPI 包 `traderharness` 1.1.0（Research Beta）、mkdocs 文档站、CI、Dockerfile、CHANGELOG 齐全，并且已经跑过一组 21 个交易日的"魔鬼窗口"基准（沪深 300 区间 -9.12%），公开了四个模型的区间收益 / 夏普 / 回撤 / 胜率对照表。

| 层 | 他们的做法（已核对仓库） | 对我们的启示 |
|---|---|---|
| 引擎 | 纯 Python 包，`core/` 下 engine / env / events / portfolio / calendar / budget / runner 各自成文件；依赖只有 pandas / numpy / httpx / pyarrow | 先定死 core 六件事：模拟时钟、观测、账户、撮合、事件、预算。不要一开始就碰界面 |
| 抗污染 | `masking.py` / `entity_masking.py` / `leakage.py` 三个独立模块，而不是一个开关函数 | 我们文档里的"五开关"应一开关一模块，可单独写单测、单独做 A/B |
| 服务 | FastAPI + uvicorn（`server/app.py`），另有 `run_manager` 与 `paper_manager` 两个生命周期管理器 | 运行生命周期 ≠ 模拟盘会话，要分开管理；前端只订阅事件流 |
| 前端 | React 19 + Vite + React Router + lucide-react；`webui/e2e` 用 Playwright | 原型阶段单文件没问题，开发期必须换 Vite + 组件化，否则图表和表格会失控 |
| 回放 | 轨迹是 `.jsonl`，demo 回放（`momentum_dragon_2024-03-14.jsonl`）打进 wheel 随包分发，做到"零凭据三步体验" | 把"可回放"尽早定成 jsonl 事件格式，并内置一条样例轨迹用于现场演示 |
| 数据 | 可选依赖 `baostock` / `mootdx` / `duckdb`，覆盖五年全市场日线与 5 分钟线 | **强信号**：A 股历史行情免费源可行 → 数据风险下调，真正要验证的是新闻/公告的时点快照 |
| 交付 | PyPI 包 + 文档站 + CI + Dockerfile | 期末至少要有"可 pip 安装、一条命令跑起来"的形态 |

一个必须正视的事实：它已有可复现的小基准。这类东西比再多三页产品文档都更能证明系统真的存在——这是期中之后我们最该补的一项。

## 3. 我们的现状诊断（基于实拍三页）

### 3.1 硬伤：涨跌配色反了

原型 CSS 是 `.positive{color:#28724c}`（绿涨）、`.negative{color:#ab4545}`（红跌）——**美股习惯**。但产品明确定位 A 股（TraderHarness 绿涨是它的选择，PanWatch 用红涨绿跌）。对一个面向 A 股投资 Agent 的产品，开户第一天就会被用户指出。必须改为默认红涨绿跌，并在设置里留切换。

### 3.2 三页逐条

| 页面 | 好的 | 问题 |
|---|---|---|
| **Agent 工作室** | 卡片层级清晰、CTA 明确、"带上自己的 Agent"空状态设计得体 | 没有全局状态（今天在跑什么、最近 3 次运行结果）；"最近运行"只有一行文字，没有任何指标 |
| **训练场** | 四指标 + 会话/账户同屏是对的；**订单审批块（批准/修改/拒绝 + 查看依据）是我们的独有优势** | **没有净值曲线**；事件是气泡+小字，不像台账；数字未等宽、未对齐；会话占 70%、账户 30%，比例失衡 |
| **结果与复盘** | 文案克制（"样本不足，不排名"很专业） | **零图表**；只有 6 行 label:value；"下一步改进"是空卡片；看不出回撤、胜率、基准对比——作为"复盘"页功能性最弱 |

### 3.3 全局观感

- 卡片套卡片（card in card），圆角 16px、留白 32px+，整体像文档站不像工具。
- 信息密度大约是对手的 1/3；屏幕上"可被判断的量"太少。

## 5. 设计方向

### 5.1 保留

- 浅纸底 `#F4F5F1` + 墨绿 `#345D45` + 橙点标识——这是我们的身份，而且比全暗更适合投影与打印。
- 衬线品牌字（Georgia）。
- 克制的文案语气（"样本不足，不排名"这类）。

### 5.2 引入

1. **深色数据带**：KPI 条、图表底板、事件台账、原始 JSON 一律用 `#16241C` 深色块 + 等宽数字，与浅纸骨架形成"叙事 / 仪器"两层反差。
2. **图表三件套**：净值曲线（含基准）、水下回撤、成交/工具分布。手写内联 SVG，不引第三方库（保持单文件可部署）。
3. **事件台账化**：序号 + 时间 + 类型 chip + 智能体 + 自动滚动；类型：观察/研究/工具/证据/订单/审批/规则/错误。
4. **可信度徽章条**（常驻页头）：资料时点 · 研究出口 · 轨迹完整性 · 样本量 · DSR。参考 QC 的 "Likely Not Overfit" 写法，做成本产品的语言：`时点严格` ` `证据可追溯` ` `样本不足，不排名`。
5. **运行对比页**（新增一级页面）：多曲线叠加 + 横向排名表 + 相对基准列。
6. **逐笔复盘抽屉**：成交列表 → K 线 → 决策链 → 原始动作 JSON。
7. **数据来源与时效标注**：每块数据旁标 `数据截至 2024-04-22 23:59`、`来源：实验快照 v0.3`，学 PanWatch 的行内标注。

### 5.3 禁止

- 聊天气泡承载审计信息（它是"对话"，不是"记录"）。
- 卡片套卡片。
- 复盘页没有图。
- 像素办公室当主视觉（可做彩蛋，不做首屏）。

## 8. 工程量与风险

- 原型是单文件 58 KB HTML，无构建、无依赖。图表用手写 SVG，预计 +800～1200 行，体积可控在 120 KB 内，GitHub Pages 直传即可。
- 风险：手写 SVG 必须处理空数据 / 单点数据 / 全部为负 三种边界，否则汇报现场会白屏。改完会跑一遍 Playwright 三页截图回归。
- 风险：密度提升会牺牲"留白的美"。原则是**缩卡片内距而不是缩字号**，正文最小 13px。
- 竞争风险（新增）：TraderHarness 已发布 PyPI 包与基准结果。差异化不能停留在"我们也做训练场"，必须落在**人机协同审批 + 证据编号 + 接入向导**这三项它没有的能力上。
- 数据风险（下调）：对方用 baostock / mootdx / duckdb 免费源拿到五年日线与 5 分钟线，说明行情侧可行。风险集中到"历史新闻 / 公告的时点快照"这一件上。
