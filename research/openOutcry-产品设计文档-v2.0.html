00

产品定位与五步单向闭环

我们在访谈中发现，真正阻碍用户把真金白银交给投资 AI 的是两类截然不同但同源的卡点：老股民敢用 AI 看新闻，但看不到它在真实市场规则下的历史战绩，也没能力自己搭考场；懂技术的个人开发者能折腾 Prompt、模型与 Skill，但改完配置放到实盘跑两天，分不清赚钱是因为策略变强还是大盘碰巧涨了（“蒙眼拧螺丝”）。

因此，openOutcry 必须满足三项硬约束——容易接入、过程可理解、可重复对照，并通过严格的五步单向用户旅程贯穿始终（彻底告别旧版 7 页来回横跳的反直觉导航）：

导航降权原则

协议与 Skill (/protocol) 与 产品说明 (/guide) 属于工程与参考资料，不再与 5 个业务页面平级混排，统一收拢至侧边栏底部无序号「参考 / Reference」分组，且清理 Product Spec (MDX) 等研发内部术语。

02

深度专题 A：如何科学配置一场训练（标的池应该尽可能大吗？）

用户发起一次历史训练时，最容易踩的两个坑是：① 标的池太小导致“开卷作弊”（如果只放 5 只你事后知道涨得好的股票，Agent 闭着眼买都能赚钱，这就是学术界批判的 Selection & Survivorship Bias）；② 标的池太大导致“上下文爆炸与算力失控”（把全 A 股 5,000 只股票的 K 线和公告全塞进 Prompt，既塞不下，也会让模型迷失在噪音里）。

2.1 核心解法：参考 TraderHarness 与真实模拟盘，采用「底层宽池 × 工具筛查 × 焦点池」三级漏斗

真人老股民在同花顺/东方财富模拟盘里，账户权限永远是全 A 股可买（5,000+ 只），但没人会同时盯 5,000 只股票——真人是通过「看大盘宽度/板块异动 → 选股器初筛 → 加自选股 → 盯 5–15 只重点股交易」来工作的。TraderHarness 也在工程上验证了同一范式：本地底库覆盖五年全市场 A 股（~5,000 只含历史退市/停牌股），但 Agent 通过受控工具按需筛选，而分钟级监控只跟踪 8–20 只焦点关注池（持仓 + 观察清单 + 条件单）。

LAYER 1 · 可交易底池（Universe）
尽可能宽 · 300 ~ 5,000 只

考选股能力 + 防幸存者偏差。按模拟日期真实还原当时在市股票（保留当日后退市股、排除当时尚未上市股），显式标注 ST 与停牌状态。绝不一次性塞给 LLM。

LAYER 2 · 受控工具初筛（MCP Screener）
按需查询 · 20 ~ 50 只

盘前只向 Agent 推送市场宽度、指数与板块摘要；Agent 自主调用受控工具（market.screen / research.announcements / Python 沙箱）从底池中按自身策略筛出候选股。

LAYER 3 · 活跃焦点池（Watchlist）
精准聚焦 · 5 ~ 20 只

由当前持仓 + 盘前筛出的候选股 + 活动条件单标的动态组成。精细行情、公告深读、分钟级撮合与监控只覆盖这层，Token 与 I/O 成本恒定可控。

2.3 一次训练委托单（Mandate Ticket）的完整不可变契约

参考 TraderHarness 的 RunForm 与我们的实验可复现目标，一次训练委托单 = 最小实验单位，开具后全部参数冻结成不可变快照（Snapshot Hash），修改任何一项必须「复制配置重跑」生成新委托编号：

契约组 01 · 时空与抗污染

历史窗口 × 基准 × 双重遮罩

  • 历史区间：起止交易日 + 自动计算交易日数，低于 60 日实时提示“仅用于冒烟/演示，不纳入正式排名”；支持一键选经典考场（如 2024 震荡市 / 急跌魔鬼窗）。
  • 抗污染双开关：默认强制开启 PIT 时点截断 + 日期/实体双盲遮罩（含固定 Seed）；允许高阶用户显式切换为「配对实验（Masked vs Unmasked）」测模型是否在背题。
契约组 02 · 标的池与筛选权限

底池档位 × 关注池上限

  • 标的池：三档切换（全市场 A 股 / 沪深 300 / 专项自选），透明展示当时在市家数与剔除规则（ST、停牌、涨跌停一字板）。
  • 焦点池上限：默认单日重点深研不超过 12 只（防止单日 Token 失控），由 Agent 通过受控工具动态维护自选清单。
契约组 03 · 团队与单执行者边界

1–3 位 Agent × 职责隔离

  • 单 Agent 模式：全能研究与下单（默认）；
  • 多角色委员会（1–3 位）：借鉴 TraderHarness 单执行者原则——勾选第 1 位为主交易员（唯一持有 trade.submit_order 工具），第 2/3 位为研究员 / 风控官（只读输出备忘录与否决建议），杜绝多头同时改账导致归因混乱。
契约组 04 · 资金、规则与时间节拍

A 股规则 × 协作模式 × 预算闸门

  • 资金与成本：初始资金（如 ¥100,000 / ¥1,000,000）、佣金（万 2.5 最低 ¥5）、印花税（卖出千 0.5）、滑点（如 3 bps），成交一律使用未复权真实历史价（分红送转由引擎确定性入账）。
  • 决策节拍与协作：选定时间粒度（MVP 默认日频三阶段）+ 逐案确认 (HITL) / /goal 自主推进 + 单日最大工具调用与 Token 预算上限。
03

深度专题 B：如何把控训练时间粒度（快慢双时钟解耦）

在股票市场中，历史行情最细可以精确到秒级/Tick，而一只 A 股单日最高点与最低点振幅动辄超过 10%–20%。但如果我们照搬高频量化策略让 LLM 逐秒决策，60 个交易日（约 288,000 个 3 秒快照）需要耗时 16 天以上、烧掉数千美元 API 费，且 A 股 T+1 制度决定了当天买入本就不能当天卖出，高频唤醒反而诱发大模型噪音交易。

因此，openOutcry 确立核心架构范式——「快慢双时钟解耦（Dual-Clock Harness）」：把「Agent 思考唤醒频率」与「市场撮合/风控扫描频率」彻底分开。

6.1 必须严格遵守的四条状态机不变量

INVARIANT 01 · 审批 ≠ 成交

四段独立订单生命周期

order.proposed（意图）→ order.approved / submitted（人机确认，现金与持仓零变化，附 3 秒撤销缓冲）→ rule.checked（确定性规则校验）→ order.filled / rejected / unfilled（推进时钟至撮合窗口后才更新账本）。

INVARIANT 02 · 两套审批绝不混用

协议级权限 vs 业务级订单

对齐 A-1 文档：外部 Agent 通过 ACP 发起的越权本地命令（如 Bash）一律自动拒绝并在输入框上方弹只读告知横幅；所有交易决策必须通过受控 MCP trade.submit_order 进入右侧订单票据审批，确保完全可审计。

解决“蒙眼拧螺丝”的核心视图

  • 异常回炉闭环：禁用 /goal 无确认自动下单；当发现 Agent 在实盘某类行情判断失准时，支持将对应持仓与时间窗带回 /studio 历史训练场重跑改进。
