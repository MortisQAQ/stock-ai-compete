# openOutcry 期末答辩整体结构与产品叙事大纲

> 版本：v2 · 2026-11-11；适用：2026-12-07 英文 FYP 期末答辩。
> **定位**：产品价值叙事 + 工程成果答辩，不是商业广告，也不是纯算法 Benchmark。
> **时间预算**：主讲约 18–19 分钟（含约 3 分钟演示），余下为提问；页数仅为规划建议。
> **依据**：[本项目评分与安排](README.md)、[第一部分现有设计稿](第一部分-背景与潮流引入-设计与演讲稿.md)；参考 [Kansas State University 项目汇报指南](https://textbooks.cs.ksu.edu/cis598/0-introduction/05-final-presentation/) 和 [UIUC ECE 445 结题汇报要求](https://courses.physics.illinois.edu/ece445/guidelines/final-presentation.asp)。

## 一句话主线

**金融 Agent 已从生成观点走向实际使用（背景）→ 投资者需要检验、理解和改进自己的 Agent（需求）→ openOutcry 提供可接入、可试炼、可复盘的方案（设计）→ 用产品流程与可核验证据展示做到了什么（实现与验证）→ 总结价值、边界和下一步。**

## 整体目录（保留原定四幕 + 收尾）

| 部分（目录页显示名称） | 要回答的问题 | 内容范围 | 建议时长 |
| --- | --- | --- | ---: |
| **01 Introduction — Background & Motivation** | 为什么现在值得关注这个问题？ | 项目定位一句话；金融 Agent 商业落地和社区热度；**只抛出尚未解决的核心问题**；最后一页 **Presentation Roadmap**。 | **2.5 min** |
| **02 User Problems & Requirements** | 谁遇到了什么困难，需要什么？ | 两类用户；典型任务场景；现有替代方案的不足（简洁对比）；提炼 3–4 项可检查的用户需求。 | **2.5 min** |
| **03 Proposed Solution & System Design** | 我们打算怎样解决，设计为何合理？ | openOutcry 的产品价值、核心使用闭环、三大工作区与整体架构；挑 2–3 项关键设计取舍（如 A 股约束、人工介入归因、时点控制）。 | **4 min** |
| **04 Implementation, Demo & Evaluation** | 我们实际做出了什么，有何证据？ | 本学期实现范围与可运行模块；围绕一个真实使用场景做约 3 分钟 Demo；测试/运行结果、可复现依据、限制与未完成项。 | **8 min** |

**合计 18.5 分钟。** Roadmap 中保留这五个条目（四幕 + Closing），不要将其误改成“Introduction / System Design / Demonstration / Conclusion”四块——那会消掉原定的独立用户需求部分。

## 每部分的明确边界（防止重复）

- **01 负责提出疑问（Why now）**：承认闭源投研工具在单次问答方面已经很强；用一句话引出“用户自己的 Agent 在连续 A 股试炼中表现如何、调优是否有效”，**不**展开竞品四象限、用户画像、需求清单或方案细节。
- **02 负责定义问题（For whom / What）**：讲用户工作流的障碍、替代方案缺口和验收需求，**不**提前详解工作区、事件账本、网关或前端界面。
- **03 负责解释方案（How designed）**：展示用户需求如何映射到产品与工程设计、为何选这些机制，**不**逐屏操作产品或宣称未经验证的效果。
- **04 负责提交证据（What built / Does it work）**：基于真实实现、Demo 和测试结果验证第 03 部分的设计；如果某能力还在规划中，要明确标成“计划/原型”，**不**把未来功能描述为已完成。
- **Closing 只收束**：把“已实现、尚未实现、下一步”说清楚；不重复架构与完整操作过程。

## Introduction 中 Roadmap 的位置

保留目前第一部分的**市场落地 → 开源/社区关注 → 关键追问**的展开方式；已有供给缺口分析（当前 Slide 05）移到第 02 部分精简讲。原第一幕的定位收束（当前 Slide 06）可压缩为**问题一句话 + Roadmap**，放在 **Introduction 最后一页**（总页码待全片编排后确定，不强制叫 Slide 05）。

这样从“为什么会提出这个问题”进入“哪些人真正被这个问题困住”，不会在第 01 幕提前讲完第 02 幕。

## 内容真实性与答辩底线

1. **定位**：面向投资者与 Agent 使用者的 A 股历史模拟试炼、决策留痕及配置调优平台；“训练”主要指配置迭代与结果复盘，**并非保证模型权重训练或未来收益**。
2. **竞品表述**：区分闭源投研助手、公开模型竞技场、量化框架、传统模拟盘的不同用途；强调组合使用上的缺口，避免声称“市面上都做不到”。
3. **验证优先**：不能只展示界面效果；必须对齐本项目评分表中的 problem understanding、proposed approach、amount of work、results & conclusions，给出可观察的工程/测试证据。
4. **后续分稿**：本文件只管顺序、职责与时间。逐页设计、口播与演示脚本另行维护；第一部分网页 PPT 目前仍是旧 6 页版本，**本次不直接改网页 PPT 或逐字稿**。
