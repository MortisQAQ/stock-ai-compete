## 0. 核心共识：这场答辩的本质是什么？

**openOutcry 本质上是一个面向真实用户的产品，而不是一篇单纯造指标的算法论文。**

因此，期末答辩（2026-12-07，全英文，30 分钟槽位 = 约 18–19 分钟主讲 + 10 分钟 Q&A）要做的事情非常纯粹：**向台下的导师与评委「推销」这款产品——讲清楚它为谁而生、解决了什么真痛点、为什么现有工具都做不到、我们的产品长什么样、为什么它是一个真正值得做的项目。**

只要把“为什么这个产品值得被造出来、而且我们已经把它做出了雏形”推销成功，课程评分表里的问题理解（10%）、方案设计（15%）、工程工作量（15%）、结果结论（20%）和表达清晰度（15%）会顺理成章全部拿到，不需要生硬套八股论文模板。

## 1. 外部方法论参照：优秀产品推销与产品文档是怎么搭架子的？

综合一线产品团队最成熟的四套产品推销（Product Pitch）与产品文档（Product Spec）方法论，优秀的推销叙事高度一致：

| 框架与出处 | 核心结构拆解 | 对 openOutcry 答辩的直接启发 |
|---|---|---|
| **Andy Raskin 战略叙事五步法**<br>([The Greatest Sales Deck I've Ever Seen](https://medium.com/the-mission/the-greatest-sales-deck-ive-ever-seen-4f4ef3391ba0) / [Library of LLM](https://libraryofllm.com/sources/raskin-strategic-narrative)) | 1. 点出世界正在发生的不可逆剧变（Big Shift）<br>2. 揭示沿用旧工具的代价（Winners & Losers）<br>3. 描绘用户真正渴望的新状态（Promised Land）<br>4. 把产品功能作为跨过障碍的武器亮出（Magic Gifts）<br>5. 拿出可兑现承诺的证据（Evidence） | **不要一上来就讲自己的架构或技术细节**。先讲“人人开始用 AI 辅助炒股 / 搭 Agent”这个大变化，再讲为什么不敢真跟单，最后把产品三大模块作为破局武器亮出来。 |
| **April Dunford《Sales Pitch》两段八步法**<br>([Lenny's Newsletter](https://www.lennysnewsletter.com/p/how-to-build-a-killer-sales-pitch) / [Summary Notes](https://www.willpatrick.co.uk/notes/sales-pitch-april-dunford/)) | **前半场 Setup（建立共识）**：① 市场洞察 → ② 盘点现有替代方案的各自缺陷 → ③ 对齐“理想产品必须长什么样”<br>**后半场 Follow-Through（亮出产品）**：④ 产品品类定义 → ⑤ 差异化价值与实机演示 → ⑥ 实证验证 → ⑦ 边界与异议回应 → ⑧ 下一步路线 | 推销的核心不是吹自己全能，而是**帮听众看清市面上所有现有选择（问财、量化软件、AI 榜单、普通模拟盘）各自的硬伤**，让听众自己得出结论：“确实缺了中间这一块！” |
| **Amazon 逆向工作法（PR/FAQ）**<br>([Working Backwards](https://workingbackwards.com/resources/working-backwards-pr-faq/)) | 先写面向用户的发布通稿：**目标客户是谁 → 客户此刻卡在哪 → 现有方案为什么让人失望 → 新产品如何直观解决 → 用户上手体验如何**；最后附 FAQ 回答严苛的技术与边界追问 | 把底层技术（如时点截断、沙盒预检、A 股撮合细节）放在“产品为什么可靠”和 FAQ 层，**绝对不要拿技术约束喧宾夺主替代用户痛点**。 |
| **Basecamp 产研立项法**<br>([Sequoia Pitch Deck](https://www.roundfunded.com/en/blogs/sequoia-pitch-deck-template-2026) / Shape Up Pitch) | 1. Problem（真实受挫故事）→ 2. Why Now（市场时机）→ 3. Solution（核心交互闭环走查）→ 4. Rabbit Holes（提前排掉的暗坑）→ 5. No-Gos（明确不做什么） | 证明“这是一个值得做且能做成的项目”，不仅要展示主流程，还要展示**提前排掉了哪些暗坑**（如人工改单污染 AI 归因、马后炮新闻泄漏），以及**克制的 MVP 边界**。 |

> **方法论提炼出的第一铁律**：
> 在产品推销中，**「用户想完成什么任务却卡住了」永远是第一因（Why）**；而「抗污染、时点网关、确定性账本、严格/探索分级」是**保证产品不忽悠用户的底层壁垒（How / Secret Sauce）**。顺序一旦颠倒，产品就会退化成没人关心的自嗨工具。

## 2. 关键纠偏：为什么「LLM 交易评测全是开卷考」不成立？真正的问题是什么？

### 2.1 对上一版（v0）的纠偏记录

在 v0 初稿中，曾把 Block 1 的核心问题设为*“为什么现在的 LLM 交易评测全是‘开卷考’（预训练记忆化污染）？”*——**这个立论作为产品起点是不成立的**：

1. **搞错了主角与痛点层级**：没有任何一个真实投资者或开发者早上醒来会痛苦于“学术界金融大模型 Benchmark 存在预训练语料泄漏”。“抗污染 / 防偷看未来”是我们造这台试炼设施时必须守住的**工程可靠性底线**，而不是用户需要这款产品的**原始动机**。
2. **推导不出完整的产品形态**：如果问题仅仅是“评测开卷考”，那写一个命令行脚本把日期遮住跑一遍 CSV 就够了，根本解释不了为什么我们要做 **Agent 委托台、开放接入协议、VS Code 式三栏工作台、人机协同改单审批、逐笔证据复盘与单变量重跑**。

---

### 2.2 还原并完善：背景、真正的用户痛点与核心需求（对应主干 1 & 2）

基于前期飞书总纲文档（第 2 节竞品调研、第 3 节创新点）与 MVP 产品文档，经过补充与结构化打磨后，**真正的背景、问题与需求链条**应当这样展开：

#### 第一步：介绍背景（正在发生的真实浪潮）
- **AI 已经全面进入股票研究与交易辅助，并正在从“单次问答”走向“配置专属 Agent”**：
  - **大众与闭源侧**：同花顺问财、东财妙想、Kimi 等 AI 助手已成为投资者搜公告、读财报、问“该加仓还是减仓”的日常工具；问财甚至推出了金融 SkillHub，让用户把选股、诊股技能直接装进自己的 AI 助手里；
  - **开源与开发者侧**：以 `TradingAgents`（GitHub 11.8 万星）为代表的多智能体框架，以及 Claude Code / Codex / ZCode / Kimi 等通用 Agent 快速普及——越来越多用户不再满足于临时问一句，而是尝试配置一个带有自己投资思路（系统提示词 + 工具集 + 角色分工）的投资 Agent；
  - **社区关注侧**：“给几个主流大模型各 10 万炒 A 股”的实测对战在中文社区动辄近十万播放，券商也开始举办 AI 模拟交易赛，人人都在关心 AI 到底能不能帮自己赚钱。

#### 第二步：当前用户面临的真正问题（“AI 说得头头是道”与“真敢拿钱跟单”之间的断层）

先明确**我们的产品服务谁**：
- **用户画像 A｜有投资经验、但技术经验不足的投资者**：自己有选股和风控思路，也在日常用 AI 看盘，想拼装一个懂自己策略的投资 Agent，但不会从零写量化回测代码；
- **用户画像 B｜已经在用现成 Agent 的进阶玩家 / 开发者**：手里已经在日常使用 Codex、Kimi、ZCode、`TradingAgents` 等工具，不想放弃顺手的工作流，只想把它们拉进 A 股检验真实水平并持续调优。

当这两类用户面对同一个灵魂拷问——**“我到底怎么评判这个 AI 的成果？如果真按它的建议在 A 股买卖加减仓，我到底能不能赚钱、敢不敢跟？”**——市面上现有的四类产品**全部卡在半路**：

| 现有方案类别 | 代表产品 / 项目 | 它们做了什么 | 用户撞上的真实痛点（为什么满足不了需求） |
|---|---|---|---|
| **① AI 投顾 / 观点分析类** | 同花顺问财、Kimi、GitHub 分析类开源项目（含 `TradingAgents` 默认评测） | 搜热点公告、多空辩论、生成投研报告、给加减仓建议 | **“只管给建议，不管算实战总账”（信不过）**：事后看逻辑永远头头是道，但没有统一可量化的检验标准——真放到 A 股里，算上 T+1 当天买次日才能卖、涨跌停封死、仓位现金约束和手续费印花税，这套建议到底赚钱还是亏钱？最大回撤能不能承受？没人替用户算清楚。 |
| **② 公开 AI 交易榜单 / 竞技场** | TradeRank、Alpha Arena (nof1) | 官方挑十几个大模型自动对战，展示收益率排行榜 | **“只能当观众看戏，不能服务用户自己”（用不上）**：闭源黑盒、普通人只能看不能用；主要测加密货币和美股，缺 A 股制度支持；且全程纯 AI 黑盒运行、没有 **Human-in-the-Loop**。看别人测裸模型，用户依然不知道自己的策略和 Agent 下场会怎样。 |
| **③ 传统量化回测框架** | 聚宽、Lean、NautilusTrader、Qlib | 提供严谨的代码策略历史回测与绩效统计 | **“只认死代码，装不下活 Agent”（门槛高）**：要求用户把策略写成固定数学公式与 Python 代码，既把不懂编程的投资者挡在门外，也装不下“Agent 自主查资料、多轮推理、人与 AI 对话协商改单”的新交互范式（且海外引擎改写 A 股 T+1/涨跌停/除权成本极高）。 |
| **④ 券商 / 行情软件模拟盘** | 各大炒股 App 模拟交易功能 | 提供模拟账户让用户手动买卖记账 | **“只记交割流水，不记决策脑回路”（改不动）**：只留下一串买卖成交记录，不记录当时 AI 看了哪条公告、调了什么工具、为什么下这个单，更不支持人与 Agent 的过程留痕。亏了钱全靠用户自己瞎猜复盘，根本不知道下一步该改提示词、换工具还是加风控。 |

#### 从四大痛点自然推导出的「四大用户核心需求」
1. **开箱能搭 + 现成 Agent 原样接入（低门槛与零迁移）**：有投资经验没技术背景的用户，改提示词、挂 Skill 就能搭出自己的投资 Agent（**用户出投资经验，平台出底层能力**）；已有 Codex / Kimi / ZCode / `TradingAgents` 的用户，不必迁移重写，直接把现成 Agent 接进场。
2. **贴合 A 股实战规则 + 支持人机协同（Human-in-the-Loop）**：不用拿真钱试错，但账本必须严守 A 股真实规则（T+1、涨跌停、整手、真实税费），同时支持**人与 AI 多轮交互、人工审批与改单**——还原真实投资者“让 AI 辅助自己做决策”的使用方式。
3. **全过程决策留痕 + 针对性调优闭环（可复盘、可对比）**：不仅看到最终赚了多少，还能顺着任意一笔交易查回当时的资讯证据和推理依据；改完一个配置（提示词/模型/风控/工具）后，能在完全相同的历史行情下重跑，直观比较前后优劣。
4. **干净诚实的试炼底座（不自欺欺人）**：既然目的是帮用户建立进入真实市场前的可靠信心，训练场就必须在底层杜绝“AI 搜到未来马后炮新闻”“人工改单和 AI 自主成绩混为一谈”以及“跑两三天靠运气蒙出高收益”——确保用户看到的每一分改进都经得起推敲。

### 逐幕内容拆解（每一幕具体讲什么）

#### 第 1 幕｜介绍背景（2.5 分钟，2 页）
- **Slide 1｜封面与一句话价值主张**：
  - 主标题：**openOutcry**
  - 副标题：*An Open A-Share Trial & Tuning Ground for AI Investment Agents*（让投资者在真规则历史市场里试炼、看清并调优自己的 AI 交易助手）。
- **Slide 2｜行业背景与赛道洞察（基础能力已满街都是，验证与训练层还空着）**：
  - 展示两侧真实现状：一边是同花顺问财、Kimi 等闭源产品把行情查询、公告搜索、研报生成做成了标配；另一边是 `TradingAgents`（11.8 万星）、金融 Skill 插件与“AI 炒 A 股对战”内容在开发者和散户间快速出圈。
  - **点出战略判断（直接采用飞书总纲 2.3 节洞察）**：再去卷“搜新闻、画 K 线、写股评”的基础能力没有任何意义；现在整个市场真正缺的，是一个**让用户检验“我的 AI 到底能不能赚钱、怎么改才能更稳”的评测与训练层**。

#### 第 2 幕｜说明当前用户面临的问题与需求（3.5 分钟，3–4 页）
- **Slide 3｜目标用户画像（Who We Build For）**：
  - 左：有投资经验但缺编程底座的投资者（想把自己的选股风控经验注入开箱即用的 Agent）；
  - 右：手握 Codex / Kimi / `TradingAgents` 等现成工具的玩家（想原样带入 A 股考场检验调优）。
- **Slide 4｜核心痛点与现有四类产品的断层（Why Existing Alternatives Fail）**：
  - 用一张清晰的四列矩阵对比：**AI 投顾/分析框架**（只给建议不算实战账）vs **TradeRank 等黑盒竞技场**（观众看戏、无 A 股、无人工介入、闭源不可用）vs **传统量化平台**（纯代码门槛、不支持对话式 Agent）vs **普通模拟盘**（无决策与证据留痕，复盘全靠猜）。
- **Slide 5｜用户的四大核心需求（What Users Actually Need）**：
  - 收束成四个关键词：**进得来**（轻量模板 + 开放接入现成 Agent）、**测得真**（A 股制度 + 人机协同审批）、**看得懂/改得动**（全量证据留痕 + 单变量重跑对比）、**信得过**（严格时点隔离与诚实归因）。

#### 第 3 幕｜引出我们的产品，说明它为什么能解决问题（3.0 分钟，3 页）
- **Slide 6｜亮出 `openOutcry` 产品定位与核心闭环**：
  - 一句话说透差异：**别人的榜单服务于看客和模型厂商，我们的训练场直接服务于使用 Agent 的投资者本人**——帮他们在拿真金白银进场前，把自己的 Agent 测透、改好、攒足信心。
  - 展示五步核心闭环：`接入/配置 Agent → 锁定条件启动训练场 → 观察研究与人机交易 → 追溯结果与决策依据 → 改一个变量重跑`。明确首版“训练”是**面向用户的配置迭代与复盘闭环**。
- **Slide 7｜为什么它能解决上述问题（四大产品破局机制）**：
  - **开放适配器 + 轻量内置模板** $\rightarrow$ 解决“不会写代码”与“不想放弃顺手外部 Agent”的双重入场难题；
  - **A 股规则引擎 + 人机审批卡（Proposal Ticket）** $\rightarrow$ 解决“纸上谈兵”与“缺乏 Human-in-the-Loop”难题，且对人工改单做双轨留痕；
  - **事件溯源账本 + 一键复制单变量重跑** $\rightarrow$ 解决“亏得不明不白、复盘无从下手”难题；
  - **平台托管时钟与受控研究网关** $\rightarrow$ 解决“Agent 偷看事后新闻自欺欺人”难题，保证测试成绩真实可信。
- **Slide 8｜极简克制的产品信息架构（Three Workspaces, Zero Clutter）**：
  - 说明飞书产品文档的设计哲学：把队列、沙盒预检、时点过滤、撮合清算等复杂机制全部下沉为平台底座，前端只向用户暴露最清晰的三个主工作区：**① Agent 工作室与接入 → ② 训练场 → ③ 结果与复盘**。

#### 第 4 幕｜介绍我们的产品：功能深潜、实机演示与效果验证（8.0 分钟，7–8 页 + 3 分钟 Demo）
按照用户实际使用产品的顺序，把飞书 MVP 文档里的精华完整呈现出来：

- **4.1 第一站：Agent 工作室与开放接入（Studio & Onboarding，2 页，1.5 分钟）**
  - **委托单模型（Mandate Snapshot）**：用户不填杂乱参数，而是签发一张锁定「历史时段 × 股票池 × 初始资金与 A 股规则 × 多角色团队（研究/交易/风控）」的不可变运行快照。
  - **外部 Agent 接入边界与「严格运行 vs 探索运行」**：展示平台管时钟/观察/规则/账本、外部 Agent 只提动作（`research / order / hold / cancel`）的清晰切口；通过预检的标为 **严格运行**，本地环境不可控的外部 Agent 也能进场体验但自动标为 **探索运行**（不混入严格对比）。

- **4.2 第二站：受控训练场（Training Ground，2 页，1.5 分钟）**
  - **VS Code 级三栏同屏工作台**：左栏看 Agent 思考与折叠证据条、中栏管账户净值走带与订单审批卡（批准 / 改参双轨留痕 / 驳回）及 T+1 持仓、右栏切多时段任务切片。
  - **支撑训练场真实性的两个底层引擎**（配飞书文档流程图）：
    1. **受控时点研究网关**：所有资讯检索绑定模拟日 $D$ 硬截断至 $D-1$ 23:59:59，越界统一返回无差异空结果；
    2. **四段式订单流转**：清晰拆分 `Agent 提案 → 人工审批/修改 → A 股规则校验（T+1、涨跌停、整手、税费） → 撮合成交/拒单`，并支持零模型调用的确定性原轨迹回放。

- **4.3 实机产品演播（Live / Recorded Walkthrough，1 页导览 + 3.0 分钟实机画面）**
  - 以真实用户视角丝滑走完一遍闭环：`在 Studio 创建委托` $\rightarrow$ `在 Training Ground 查看受控搜索证据、在审批卡上手改一笔委托股数并观察双轨记录与 T+1 账本变化` $\rightarrow$ `跳到 Review 页顺着收益曲线点开一笔败笔交易查回原始证据，点击复制配置改风控提示词重跑`。

- **4.4 第三站：结果复盘、调优闭环与实证案例（Review, Iteration & Pilot Case，2 页，2.0 分钟）**
  - **白盒逆向追溯链**：展示如何从 `收益率/最大回撤` 一路穿透回 `订单 → 成交/规则拒单 → 结构化动作 → 证据编号 → 运行快照`，配合工具消融视图定位到底是“漏看公告”“违反 T+1 规则”还是“仓位过猛”。
  - **诚实置信门禁 + 首轮真实运行切片验证**：展示样本过少或人工介入时产品自动标注 **「无法判断 / 探索运行」** 的防误导设计；并放上我们在固定 A 股历史窗口跑通的首组真实测试轨迹，用直观对比证明：**用户真的能靠这套产品发现 Agent 的风控漏洞并调优出更稳的版本。**
