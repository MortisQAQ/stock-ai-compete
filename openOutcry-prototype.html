№ 04 — Connect 设计稿 · 未执行真实授权

把熟悉的 Agent 带进来。

Skill 引导接入，本地 Runner 管理会话。你仍然在 openOutcry 里查看每一次研究、订单与审批，凭据不写入轨迹。

01

安装 Skill

在你的 Agent 环境里安装 openOutcry Skill，它负责发现训练场、读取受控资料并提供标准动作格式。

$ openoutcry skill install
# 仅注册能力，不上传凭据
02

启动本地 Runner

Runner 在你的机器上持有模型凭据并驱动 Agent；平台只接收观察结果与动作意图，不接触密钥。

$ npx openoutcry-runner --port 7431
✓ waiting for handshake
03

握手与预检

平台检查协议版本、动作格式与工具白名单。预检不通过时说明阻断原因，不会静默切换模型。

Boundary接入边界

Skill 负责发现并使用训练场；MCP 只暴露当前实验允许的研究工具。

训练场协议 负责 observation / action；规则引擎 负责校验、拒单、撮合与账户变更。

外部 Agent 只能提出动作，不能直接成交，也没有资金转移权限。断线、心跳超时或动作解析失败时暂停运行并说明原因。

本地接入默认自动授权，不导出长期密钥；凭据不写入轨迹，也不进入导出的 JSON。

01 — Observation

      
环境只给观察

      
模拟时钟、账户、持仓与受控资料。所有资料带截止时间与证据编号，晚于截止时间的资料物理不可见。

    

    

      
02 — Action

      
动作必须结构化

      
Agent 只能提交标准动作：下单、止损、请求资料。解析失败即暂停，不做猜测式补全。

    

    

      
03 — Event

      
事件不可改写

      
每一次提案、审批、拒单与撮合都追加为事件，带序号与时间戳，可离线回放。

№ 06 — Product Brief

      
一个入口，完成一次改进。

      
本文件合并 Agent 工作室与模拟交易场原型；详细产品规划仍保留在 Markdown 文档中。

    

    Prototype
  


  

    

      
01

      
准备 Agent

      
内置模板或本地接入 → 配置提示词 → 选择训练场模板。Skill 和协议放在辅助入口，不干扰日常操作。

    

    

      
02

      
在训练场里跑

      
固定历史时间、股票池、资金与规则。Agent 只能通过受控出口研究，提出的订单先成为提案，再由人批准、修改或拒绝。

    

    

      
03

      
复盘并改一个变量

      
看净值与回撤、看逐笔证据，复制配置、只改一个变量重跑，再与旧版本对比。

    

  


  

    
为什么不是一个聊天框

    
聊天框能把一段分析讲得像模像样，但它无法回答三个问题：这个判断在当时的信息条件下是否成立？订单是否真的按 A 股规则成交？下一次修改到底改对了哪个变量？所以这里的主界面不是对话框，而是「观察—提案—审批—撮合—复盘」的账本。

    
为什么要有审批

    
把资金完全交给自主 Agent，在真实场景里没有人敢这么做。平台把「提出意图」和「实际成交」拆成两步，分别留档，于是报告里可以区分自主决策、人工确认和人机混合三种协作程度。

    
为什么强调样本门槛

    
二十个交易日的收益曲线看起来再漂亮，也不足以支撑排名。平台在样本不足时明确拒绝给出结论，而不是把一条漂亮的曲线当成绩效证明。

    
本原型的边界

    
所有数字、公司名与事件均为虚构样例，用于演示交互与信息结构。协议、撮合与审计能力以产品文档为准，本文件不代表已实现的服务。
