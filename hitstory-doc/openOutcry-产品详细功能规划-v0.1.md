# openOutcry 产品文档 MVP 版

日期：2026-10-16  
状态：MVP 产品初稿，待整体评审与功能冻结。文中“必须实现”是首版范围，不代表当前已经完成。

## 1. 先说清楚

### 1.1 产品定位

openOutcry 是一个面向 A 股的 LLM 投资 Agent 运行与评测设施。

它让用户把一个投资 Agent 放进受控的历史市场中，让 Agent 按当时可获得的信息研究、决策和下单，再通过可追溯的结果回答三个问题：

1. 这个 Agent 能否形成可执行的交易决策？
2. 它的表现是否建立在正确的规则和时点信息上？
3. 我应该修改提示词、工具、风控还是模型？

首版的“训练”指配置迭代、模拟演练和复盘，不指自动更新模型权重。

### 1.2 核心闭环

> 配置 Agent → 创建实验 → 受控研究 → 形成决策 → 按 A 股规则撮合 → 保存轨迹 → 查看结果 → 复制版本重跑

### 1.3 首版边界

- 只做模拟交易，不连接真实券商，不提供真实下单和收益承诺。
- 首版只做日频 A 股历史受控运行，使用冻结的数据和规则版本。
- 首版优先服务想验证和改进 Agent 的投资者与 Agent 开发者。
- 私有实验是首版主线；公共榜单、挑战赛和完整平台管理不阻塞 MVP。

## 2. MVP 只保留三块

产品不按后台服务或研究概念拆成十个入口，而按用户任务拆成三个工作区。

| 工作区 | 用户要完成的事 | 包含的能力 |
|---|---|---|
| **Agent** | 准备一个可以运行、可以比较的 Agent 版本 | 内置模板、提示词、模型、研究工具、风控参数、版本、预检、外部 Agent 来源 |
| **训练场** | 在固定条件下运行、观察和复盘一次 | 历史场景、数据与规则快照、模拟时钟、受控研究、账户、订单、运行状态、轨迹回放 |
| **结果与复盘** | 看懂表现并决定下一步改什么 | 净值与风险、订单、证据、决策时间线、失败案例、版本对比、复制重跑 |

### 2.1 合并原则

- **Agent 工作室 + 开放接入**合并为 Agent 工作区。外部 Agent 只是 Agent 的一种来源，不单独占据一级导航。
- **实验中心 + 模拟交易场 + 决策档案**合并为训练场工作区。用户只需要进入一个运行页面，不需要理解内部的队列、撮合、事件账本和数据服务。
- **决策档案 + 报告与比较**合并为结果与复盘工作区。证据、订单、轨迹和指标围绕同一次运行组织。
- **数据与规则**不做独立用户入口，作为实验配置、运行摘要和可信度说明的一部分出现。
- **首页 / 工作台**不做收益排行榜，首版直接展示实验列表、快速开始和最近失败运行。
- **榜单、公共实验、平台管理**属于后续平台能力，首版不放入主导航。

## 3. MVP 用户路径

### 路径 A：第一次运行

选择默认 Agent → 修改名称和提示词 → 选择预置历史场景 → 查看预检结果 → 进入训练场 → 查看运行进度 → 打开结果与复盘。

### 路径 B：一次有效改进

打开一笔订单 → 查看当时的观察、证据和规则校验 → 判断问题属于研究、执行或风控 → 复制 Agent → 修改一个变量 → 在相同场景和预算下重新进入训练场 → 与旧版本对比。

### 路径 C：外部 Agent 接入

选择“外部 Agent”来源 → 使用统一观察和动作协议接入 → 完成最小能力预检 → 进入训练场并保存原始输入、原始输出和标准动作 → 根据可控程度标记严格运行或探索运行。

外部接入在 MVP 中保留协议边界，但不承诺任意远程 Agent 即插即用，也不把外部聊天界面嵌入为主界面。

## 4. 三个工作区的功能定义

### 4.1 Agent：准备一个可评测版本

#### 必须支持

- 选择一个内置单 Agent 模板，开箱即可运行。
- 编辑系统提示词、输出格式和有限的研究流程配置。
- 选择模型名称、版本和推理参数；凭据只保存为安全引用。
- 选择平台预审的研究工具，并配置调用次数、token 预算和运行成本上限。
- 设置股票池、持仓上限、单笔上限和基础风控约束。
- 保存版本、复制版本、查看变更说明，已完成实验引用不可变版本。
- 启动前执行预检，失败时说明阻断原因，不静默切换模型、数据源或网页。

#### 外部 Agent 的统一边界

平台向 Agent 提供受控观察，至少包括运行 ID、模拟时钟、市场状态、账户、可见证据、规则和预算。Agent 返回标准动作：

- `research`：提出搜索或阅读请求；
- `order`：提出标的、方向、数量、订单类型和结构化理由；
- `hold`：保持现状并说明原因；
- `cancel`：取消合法的未完成订单；
- `error`：声明无法完成，不伪造成功。

外部 Agent 只能提出动作，不能直接读取交易数据库、修改账户或决定撮合规则。原始输入、原始输出、转换结果、错误、超时和适配器版本必须绑定到运行轨迹。

#### 可评测性标记

每个 Agent 显示四个状态：数据是否受控、工具是否受控、轨迹是否完整、是否允许人工介入。无法证明执行环境受控的外部 Agent 可以运行，但只能标为探索运行，不进入严格比较。

### 4.2 训练场：在固定条件下运行、观察和复盘

训练场是 openOutcry 的主体。它不是一张收益曲线，也不是把 Agent 接入后等待结果的黑盒，而是一套把市场时钟、信息出口、交易规则、账户账本和决策事件放在同一条运行链路中的环境。

#### 训练场的最小闭环

> 创建快照 → 注入当时可见的信息 → Agent 研究与决策 → 规则引擎校验订单 → 更新账户与净值 → 追加事件 → 原轨迹回放 → 复制配置重跑

训练场必须能回答“当时 Agent 看到了什么、提出了什么、平台为什么接受或拒绝、账户如何变化”。如果只能得到最终收益，产品仍然只是一个回测入口。

#### 创建训练场时确认

- Agent 配置版本、模型版本和研究助手版本；
- 固定数据集、资料库、股票池、时间窗口和基准；
- 初始资金、费用、交易规则和运行模式；
- 研究预算、超时和有限重试；
- 是否启用实体匿名和证据引用要求；
- 是否允许人工干预，以及该运行是否可进入严格比较。

创建后生成不可变训练场快照。修改提示词、数据、规则或工具只能创建新版本，不能改变已完成运行。

#### 训练场基础能力

| 能力 | MVP 必须做到 | 首版取舍 |
|---|---|---|
| 运行快照 | 固定 Agent、模型、Prompt、数据、资料库、规则、窗口、股票池、资金和预算 | 不支持运行中修改配置 |
| 模拟时钟 | 区分研究、决策、提交、撮合、结算和下一阶段可见状态 | 首版只做日频，不假装还原分钟级微观撮合 |
| 受控研究 | 只返回当前时点合格的搜索、阅读和证据整理结果 | 不承诺重建某一天的全部互联网 |
| 交易场 | 处理订单意图、规则校验、成交或拒单、账户和净值 | 暂不处理复杂公司行为和完整集合竞价 |
| 事件账本 | 追加保存观察、工具、证据、动作、订单、账户、错误和预算 | 不把不可验证的自由文本思维当作审计证据 |
| 回放 | 不调用模型和互联网，重现当时实际事件与返回内容 | 重新推理单独生成新运行 ID |
| 比较 | 在同数据、规则、窗口和预算下比较两个版本 | 首版不做自动提示词搜索 |
| 运行控制 | 启动、中止、查看状态，保留中止前的全部记录 | 断点恢复放入后续版本 |
| 导出 | 导出脱敏 JSONL 或 Markdown 事件记录 | 不在 MVP 做排版型 PDF |

#### 首版运行方式

- 采用日频历史运行，研究和决策时点明确，成交使用后续预定时点的市场数据。
- Agent 不能在决策前看到未来成交价或当天尚不可见的完整收盘信息。
- 平台提供 `search_evidence`、`read_evidence` 和基于已读证据的结构化整理能力。
- 历史受控模式默认禁止 Agent 私自联网、读本地文件或调用未授权工具。
- 研究工具失败必须区分资料不足、版本不可确认、时间冲突、预算耗尽、服务失败和权限不足。

#### 最小 A 股规则

- T+1 可卖约束；
- 涨跌停和停牌状态；
- 现金、持仓、交易数量和最小单位校验；
- 佣金、印花税等费用；
- 订单有效期、成交、未成交和拒单原因；
- 已支持的股票板块、交易日历和费用规则按历史版本固定。

首版暂不支持的公司行为或复杂撮合场景必须在预检中阻断，不能忽略后继续计算净值。

#### 运行状态

首版支持排队、准备中、运行中、完成、失败、中止和部分完成。模型失败、格式错误、预算耗尽、资料缺失和规则拒单分别记录。

原轨迹回放不重新调用模型或互联网；重新推理生成新的运行 ID。中止后保留已有账户和轨迹，不补写未运行时段的收益。

#### 训练场运行页面

运行页面建议固定为三栏：

- **状态栏**：模拟日期、当前阶段、运行状态、现金、持仓、净值、基准和预算；
- **决策时间线**：观察、研究问题、工具调用、证据阅读、Agent 动作、订单状态、账户变化和错误；
- **事件详情**：证据版本、引用位置、结构化订单、规则校验、原始输出与解析结果。

页面重点是“发生了什么以及为什么”，不做成 Agent 聊天窗口。暂停、继续、终止等运行控制可以按底层实现进度提供；即使没有断点恢复，也必须保留已有事件并明确运行已中止。

### 4.3 结果与复盘：解释表现，而不是只看收益

结果页围绕一次训练场运行提供三个视图：

1. **概览**：净值、基准、累计收益、最大回撤、成交、费用和运行可信度。
2. **决策时间线**：按模拟时间查看观察、研究问题、已读证据、结构化理由、订单、成交或拒单和账户变化。
3. **版本对比**：把候选版本与固定基线或上一版本放在相同场景中比较，定位改善、退步和新增违规。

每一笔订单都能追溯到：当时的观察、实际返回的证据版本、Agent 动作、规则校验、成交路径和账户影响。

#### MVP 指标

| 类别 | 首版指标 | 说明 |
|---|---|---|
| 表现 | 累计净收益、相对基准收益、最大回撤 | 公开计算口径、费用和基准 |
| 执行 | 成交、费用、无效订单率、拒单原因 | 执行成功不等于投资正确 |
| 证据 | 证据 ID 有效性、证据覆盖情况、时点合规状态 | 先做可核验记录，不夸大语义评分 |
| 运行 | 超时、模型错误、预算消耗、轨迹完整性 | 失败原因与投资结果分开显示 |

样本不足时显示“无法判断”，不强行排名。夏普、DSR、幻觉率、解释质量、统计检验等指标在没有稳定口径和输入时显示“未启用”，不作为 MVP 承诺。

## 5. 可信运行的底线

### 5.1 时点信息

每条资料至少记录事件时间、首次公开时间、当前版本公开时间、平台入库时间、策略可用时间、来源和版本指纹。只有版本和可见时间可确认的资料才能进入严格历史运行。

平台必须先完成版本准入和时点过滤，再进行摘要与匿名化。研究助手可以规划查询和整理证据，但不能决定资料是否合格。

### 5.2 账户与规则

账户每次变化都必须能追溯到订单、成交、费用或公司行为。涨跌停触及不自动等于成交；在没有排队和成交量依据时使用预先声明的保守规则。

### 5.3 轨迹与隐私

轨迹采用追加式记录，至少保存模拟时钟、观察、工具调用、证据引用、原始输出、解析动作、规则校验、订单、账户变化、错误和人工干预。

模型不可验证的自由文本思维不作为完整证据。模型和数据源密钥不写入轨迹、公开配置或导出文件；导出只包含脱敏引用。

## 6. 明确不做什么

以下能力不阻塞 MVP：

- 全市场、多市场和真实券商交易；
- 完整分钟级微观撮合、集合竞价和复杂公司行为；
- 任意远程 Agent 即插即用、适配器市场和完整 ACP 兼容；
- 多角色辩论、自动提示词搜索和在线强化学习；
- 公共榜单、挑战赛、社区评审和商业化计费；
- 复杂暂停恢复、并行队列和大规模分布式运行；
- 将短期收益包装成投资能力认证。

人机协作保留为后续能力。MVP 只需要支持中止和完整记录；逐单确认、人工改单和协作对照放入 P1，并与自主运行分组。

## 7. MVP 验收标准

### 用户闭环

- 新用户可以从默认模板和预置场景开始，不需要先理解内部架构。
- 用户可以看到 Agent 版本、实验快照、运行状态和失败原因。
- 一次实验可以完成研究、标准订单、规则校验、成交或拒单、账户变化和结果报告。
- 用户打开任意一笔交易时，可以追溯到当时的观察、证据、动作和规则校验。
- 用户复制 Agent 并修改提示词后，可以在相同条件下重跑并查看差异。

### 可信度

- Agent 无法绕过平台读取未授权网络、文件和工具。
- 未来资料不会进入 Agent 上下文，越界请求不会泄漏未来资料的存在性。
- 历史运行使用固定的数据、规则、模型和提示词版本。
- 数据修订生成新版本，不静默改写旧轨迹或旧报告。
- 探索运行、不可约束外部 Agent 和人机混合运行不会混入严格自主比较。

### 可改进性

- 用户能从结果页定位一次失败属于研究、证据、规则、执行还是风控问题。
- 轨迹回放不需要重新调用模型或外部服务。
- 固定基线和候选版本可以按同一场景对齐比较。
- 报告会披露样本量、数据覆盖、模型版本、权限状态和剩余限制。

## 8. 开发顺序

### D1：运行底座

实验快照、冻结数据集、模拟时钟、账户、订单、成交、费用、净值和最小 A 股规则测试。

### D2：受控研究

时点准入、证据版本、搜索、阅读、引用、最小匿名化和未来信息拦截。

### D3：决策档案

追加式事件账本、工具调用、订单链路、错误记录、轨迹回放和运行状态。

### D4：结果与比较

MVP 指标、结果页、固定基线、版本对比、失败场景和脱敏 JSON/Markdown 导出。

### D5：开放接入与协作

本地 Runner、官方适配器、逐单人工确认、多角色、工具消融和公共实验。它们建立在 D1-D4 的统一协议之上，不改变 MVP 主线。

## 9. 本周需要冻结的决定

1. 首版主线是“Agent → 实验 → 结果与复盘”，不以榜单为首页。
2. Agent 工作室和开放接入合并；外部 Agent 是一种来源和连接方式。
3. 首版只支持日频 A 股历史受控运行，冻结数据、规则和配置版本。
4. 搜索、阅读和引用是统一研究出口，正式历史运行默认禁止 Agent 私自联网。
5. 结果必须同时展示表现、执行、证据和运行可信度，样本不足时显示“无法判断”。
6. 先证明用户能在相同条件下修改 Agent 并重跑，再扩展开放平台、协作和公共评测。

## 总结

openOutcry MVP 不是一个功能齐全的投资平台，而是一条可信、可复盘、可改进的 Agent 实验链：

> 固定信息和规则 → 运行 Agent → 记录每一步 → 看懂结果 → 修改一个变量 → 对照重跑

只要这条链路完整，openOutcry 就已经能验证最核心的产品假设：用户是否愿意因为看清 Agent 的行为，而持续改进自己的 Agent。
