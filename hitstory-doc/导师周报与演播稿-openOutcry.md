## 一、 汇报核心策略与思路

向导师汇报周报与月度进展时，切忌陷入流水账式的“按键说明书”。导师最关心的三个核心问题是：
1. **学术/工程立意是否扎实**：为什么要做这个？解决现有 AI 交易的什么痛点？（未来信息泄漏、回测高胜率假象、缺乏全量留痕）。
2. **工作推进是否连贯深入**：过去一个月到底做了什么？从第 5 周调研金融大模型“记忆化污染”（Memorization Problem、Look-Ahead-Bench），到第 6、7 周收敛产品主线，再到本周将产品文档具象化为高保真工作台。
3. **“实际做的比文档多”说明了什么**：在原型落地过程中，我们没有停留在抽象概念，而是推导出了**真正符合真实交易工程实际的架构演进**（如：从单 Agent 配置演化为**“时段 × 标的池 × 团队（交易/研究/风控）”的委托台**；从单一对话框演化为**VS Code 级三栏工作台**）。

## 三、 逐字口播演讲稿（带页面演示指引）

> **【演示准备建议】**：在终端启动 `openoutcry-web`（打开浏览器全屏至 `http://localhost:5173` 或 preview 端口），保持视口宽度在 1200px 以上，进入桌面三栏模式。

### 【开场】立项定位与真问题（1.5 分钟）
*(画面提示：全屏停留在 `№ 01 新建训练` 首页，鼠标不要乱动，眼神交流聚焦)*

“老师好！今天我想系统向您汇报一下我们项目 **openOutcry** 最近一个月的工作进展。

过去这一个月，我们主要围绕一个核心命题展开：**如何为 A 股投资 LLM 打造一个真正抗污染、可复现、过程可追溯的评测与训练场？**

我们在早期的文献与市场调研中发现，像同花顺问财、BloombergGPT 等闭源产品，预训练中已经吞掉了数万亿 token 的金融数据；而学术界最新的成果（如 *The Memorization Problem*、*Look-Ahead-Bench*）明确指出：**市面上绝大多数大模型在历史回测中跑出的所谓高夏普、高胜率，本质上是因为模型‘在预训练中记住了历史走势’，或者‘在检索工具中泄露了未来信息’。** 现有公开测试只看一个单薄的最终收益率，噪音极大，根本测不出 Agent 真实的逻辑稳定性和风控能力。

因此，openOutcry 的目标不是做一个给股民推股票的对话助手，而是**一套面向投资 Agent 的闭环测试床**：用户把任意模型或 Agent 放入固定受控的历史市场中，系统只给它模拟时点前合法可见的数据，通过全量留痕的事件轨迹，回答**‘这个 Agent 到底靠不靠谱、它的风控逻辑在什么场景下会崩塌’**。

基于这个思路，我们最近一个月完成了产品设计文档，并将其直接落成了当前这套完整的可交互 Web 原型。接下来我将对照原型页面，分两个核心模块向您详细演示。”

### 【第一部分】新建训练：从“配置页”演化为“委托台”（2 分钟）
*(画面操作：鼠标平滑移动至 `№ 01 新建训练` 页面的核心表单区与右上角深色运行卡)*

“老师请看第一个核心页面：**新建训练（Training Desk）**。

在最初的产品文档中，我们设想的只是一个传统的‘Agent 参数配置表单’。但在实际推进原型设计时，我们发现：真实的投资实验从来不是孤立考察一个 Agent，而是**针对特定的市场环境，委托一个团队去达成目标**。

因此，我们把这个模块直接重构成了一张**‘委托单（Mandate Ticket）’**。一次不可变的标准训练，由四个维度严格锁定并生成不可变快照：
1. **时间窗口**：比如固定 2024 年 4 月 23 日到 5 月 21 日。时间一旦敲定，系统模拟时钟立即锁死，后端绝对不给模型‘快进’或‘窥探后续走势’的物理可能；
2. **标的资产池**：预设核心蓝筹、指数成分股或自定义股票篮子；
3. **资金与运行模式**：支持 10 万/20 万初始资金，以及‘逐案确认’与‘自主运行’两种人机协作模式；
4. **最核心的创新是多 Agent 团队分配**：我们支持多模型或多 Agent 组合，按顺序赋予‘交易’、‘研究’、‘风控’等不同分工。例如：让具备强逻辑推理的模型抓财报，让低延迟模型算仓位，风控 Agent 做合规把关。

页面右上角有一张深色的**‘当前运行卡’**，它实时映射着当前挂起训练的模拟时钟、交易日进度和未平仓浮盈；下方则是历史训练账本，支持调阅过往委托并一键复制配置重跑。

这就完成了从‘单点模型调参’向‘标准化实验委托’的跨越。”

### 【第二部分】训练场：超越文档的 VS Code 级工作台（3.5 分钟·核心高潮）
*(画面操作：点击左侧导航栏的 `02 训练场`，整屏切换至三栏工作台，稍作停顿展示沉浸感)*

“接下来是整套系统最核心的交互枢纽 —— **训练场（Training Ground）**。

老师，在最初的产品文档中，这里只画了一个基础的三栏概念。但在实际前端开发中，为了让研究员真正能够‘看清 Agent 的每一次呼吸’，我们把它做成了 **VS Code 级别的专业级分析工作台**。

整个视口固定无全局跳动，按三栏紧密联动：

*(鼠标指向左栏)*
**首先看左栏：会话流与事件链（Conversation Pane）**：
* 这里的排版采用了类似专业研发工具的版式：Agent 的思考直接在纸面展开，我的插话采用紧凑气泡；
* **重点在工具与证据的折叠条**：Agent 什么时候调了搜索、调用了什么参数、引证了哪一条研报，都打上了严格的证据编号和时间戳。系统强制实施‘受控时点搜索’，晚于模拟时钟发布的信息全部被物理剔除；
* 当产生买卖提案或发生解析异常时，条目会以鲜明的标识突出，绝不漏掉关键决策点。

*(鼠标移到中栏顶部与中部卡片)*
**再看中栏：高密度的交易控制中心（Workbench Pane）**：
* 顶部是**账户状态走带**：账户净值、可用现金、持仓市值一目了然，所有数字都是规则引擎扣除佣金、印花税后的精确账本；
* 中间是最关键的**人机协同审批区（Proposal Ticket）**：当 Agent 给出调仓建议时，必须明确买卖方向、数量、委托限价和决策依据。**用户在这里拥有‘直接批准’、‘人工修改参数’与‘驳回拒绝’的完整控制权**。最重要的是——系统会同时记录 Agent 的原始意图与人类修改后的最终动作，在后续复盘中明确标出‘纯自主’还是‘人机混合’，杜绝人工干预后把功劳都算给 AI；
* 下方联动着当前持仓列表，严格执行 **A 股 T+1 规则、涨跌停限制与可用份额锁定**；
* 点击栏头的‘回放轨迹’，还能逐帧回放整场推演历史。

*(鼠标点击右栏的不同任务项)*
**最后看右栏：训练任务切换器（Task Switcher）**：
* 这里列出了当前委托下的不同时段或子任务切片。点击任意一项，中栏的资产和订单面板瞬间切换，便于研究员在不同行情区间做横向切片对比。”

## 四、 导师可能追问的 4 大关键问题与应答预案

### Q1: “你们这个看起来很像同花顺或量化软件的前端，你们的学术/创新点究竟在哪里？”
> **应答要点**：
> “老师，传统量化平台（如聚宽、JoinQuant）面向的是**静态数学公式和代码策略**，输入的是规整的数值矩阵；而我们面向的是 **LLM 的自主研究行为**。  
> 传统软件无法限制大模型调用联网搜索去窥探未来，也无法量化多轮对话中的幻觉与风控翻转。我们的系统是**给大模型当‘考场监考官’**：核心创新在于**‘时点受控隔离（Point-in-Time Masking）’**、**‘全量思维与证据链留痕（Evidence Trace）’**以及**‘行为稳定性（Decision Reversal Rate）量化’**。我们测的不仅是能不能赚钱，更是为什么亏钱、逻辑哪里不可靠。”

### Q2: “你们提到支持多 Agent 团队，目前这些 Agent 之间是怎么通信和分工的？”
> **应答要点**：
> “在产品架构上，我们确立了‘角色流水线（Pipeline）’模式：研究 Agent 负责调工具输出线索，交易 Agent 负责出仓位与价格提案，风控 Agent 做合规校验。  
> 目前原型先打通了核心的单 Agent 深度会话与审批链路，同时在数据结构上预留了多 Agent 团队分配字段；多 Agent 之间的仲裁总线和通信协议，正是我们在 Protocol 模块中下一步要固化的重点。”

### Q3: “你们什么时候能脱离 Mock 数据，真正跑起来一个模型？”
> **应答要点**：
> “目前前端的数据流（`RunProvider` 和 `types.ts`）完全按照真实的事件驱动模型设计，状态接口与未来后端是 1:1 对齐的。  
> 数据源方面，我们在第 6 周已经完成了《受控搜索工具设计 v0.2》，选定了 AShareHub 和智谱搜索源；下周我们将启动后端轻量 Runner 的对接，优先接入一个本地开源模型（如 Qwen/DeepSeek），跑通一个固定历史月份的完整交易切片。”

### Q4: “目前市面上有开源的 TraderHarness 等框架，你们和它们有什么区别？”
> **应答要点**：
> “TraderHarness 是我们非常尊重的技术参照物。它的时点掩码和指纹回放做得很扎实，但它的硬边界写得很清楚：**它主动停留在‘个人本地脚本工具’**，没有交互界面，更没有让人直观介入、审批和复盘的产品化场子。  
> 我们的定位是在此基础上**向前走一步**：提供高保真的交易分析工作台、人机协同审批闭环，并将其推向一个公开、常态化运行的评测平台，解决非专业程序员也能验证 AI 投资能力的问题。”

## 五、 原型与文档差异对照备忘

| 功能模块 | 原产品文档（v0.1 / MVP） | 当前原型实现（openoutcry-web） | 演进原因与价值说明 |
| :--- | :--- | :--- | :--- |
| **实验创建** | 单 Agent 参数配置表单 | **委托台（Mandate Desk）**：时段 × 标的 × 团队 × 规则 | 符合金融委托实际，支持多角色分工组合。 |
| **训练场界面** | 静态概念三栏框图 | **VS Code 级沉浸式工作台**（100dvh 固定，局域滚动） | 保证高密度专业信息同屏呈现，无需页面跳转。 |
| **交互介入** | 简单的“批准 / 拒绝”选项 | **全功能审批票（Proposal Ticket）**：支持**修改参数** | 真实记录人类介入程度，区分纯自主与人机混合。 |
| **任务管理** | 单次运行展示 | **右栏多任务切换器（Task Switcher）** | 支持在不同市场切片（牛市/熊市/震荡市）快速横跳对比。 |
| **证据追溯** | 文本提及返回证据 | **折叠式工具证据条（带有编号与时间戳）** | 穿透展示 Agent 每一条推论的数据来源。 |
