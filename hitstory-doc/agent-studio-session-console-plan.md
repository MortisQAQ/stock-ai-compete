# openOutCry Agent 工作室与会话控制台实施计划

## Summary

将 openOutCry 的 Agent 工作室和外部 Agent 接入设计为一个“会话控制台”，而不是单纯配置页或消息转发代理：

> 配置实验模板 → 安装 Skill 自动接入 Agent → 本地一键 Runner 按会话启动 Agent → Web 创建一会话一运行 → 用户通过 `/goal` 发起自主运行或通过普通输入追加指导 → 页面实时展示结构化事件流、当前 Agent、工具调用、证据、动作和运行状态。

用户始终在 openOutCry Web 控制台中工作；Codex、Kimi、自研 Agent 等作为可替换的外部 Agent Worker。Web 不复刻外部 Agent 的 IDE/终端，也不把平台做成单纯聊天转发器。

## Current State Analysis

- 根目录没有独立前端工程，当前可交付的页面是单文件静态原型 [agent-studio-prototype.html](../../agent-studio-prototype.html)。
- 当前原型已经包含连接方式、资格提示、模拟运行、审批和协议预览，但仍以“配置外部 Agent”页面为中心，尚未直观体现“一会话一运行”的完整用户旅程。
- 当前设计文档 [openOutCry-Agent工作室与外部接入设计建议-v0.1.md](../../openOutCry-Agent工作室与外部接入设计建议-v0.1.md) 已确定 MCP 负责工具接入、训练场协议负责 observation/action、事件流负责审计展示，但需要根据最新产品决策补充 Web 对话会话、Skill 自动接入、本地 Runner 和 `/goal` 模式。
- 产品规划已要求三类 Agent 汇入同一运行接口，支持实验配置快照、受控研究、轨迹回放、人工协作和外部 Agent 的严格/探索分组，见 [openOutCry-产品详细功能规划-v0.1.md](../../openOutCry-产品详细功能规划-v0.1.md)。
- 公开资料显示：MCP 适合 Agent 到工具/数据的连接；ACP 主要面向编辑器与编码 Agent；Codex App Server/SDK 适合被自定义客户端驱动并接收会话、审批和流式事件；cc-connect 的可借鉴点是本地 Agent 桥接、会话管理、Agent 切换和权限控制，但 openOutCry 还必须增加训练场时间、证据和订单边界。

## Confirmed Product Decisions

### Product entry and interaction

- Agent 工作室优先作为产品入口。
- Web 对话页是用户操作外部 Agent 的核心工作台，但不是普通聊天页。
- 一会话一运行：每个 Web 会话绑定一个 `agent_session_id` 和一个 `run_id`，避免对话上下文与实验轨迹混淆。
- 页面下方或主区域固定显示当前 Agent 名称和来源，例如 `Codex / Trading Agent`，并实时显示结构化事件流。
- 默认运行模式为“事件流 + 审批”；用户输入 `/goal` 后进入自动运行到底模式。
- 自动运行到底时，Web 输入只能追加带时间戳的指导，不可直接改写市场、账户、既定规则或历史配置。
- 用户不需要在对话里承担每个配置细节；通过表单或模板配置股票池、初始资金、时间窗口、数据集、规则、预算和评测模式。
- 首版桌面优先，移动端支持查看运行状态和处理审批，不要求移动端完成全部配置。

### External Agent connection

- MVP 首要支持本地 Runner。
- 本地部署采用一键 Runner：同一个 Runner 启动本地 Web、会话网关和按会话创建/销毁的 Agent 进程。
- 首次接入采用本地自动授权，不要求用户复制 Token 或打开外部授权流程。
- 首要对外入口是 openOutCry Skill：Skill 帮助 Codex/Claude 等 Agent 发现训练场、启动或连接 Runner、创建会话并使用训练场能力。
- MCP 用于暴露受控研究工具和训练场资源；不承担完整运行生命周期、会话持久化、实验快照、断线恢复或审计。
- openOutCry 自有训练场协议定义 observation/action；外部 Agent 必须返回 `research`、`order`、`hold`、`cancel` 或 `error` 等标准动作。
- 外部 Agent 不能直接成交，只能提出标准动作；规则引擎负责校验、拒单、撮合和账户变更。
- 外部 Agent 断线、超时或返回无效动作时默认暂停并解释，保留账户和轨迹；不自动切换内置 Agent，不静默降级。
- Web 默认展示结构化摘要；原始输出、工具参数、stdout/stderr、文件和截图作为可展开 artifact，不默认展示完整隐藏思维。
- 不复刻 Codex 等外部 Agent 的 IDE/终端，只提供统一会话、运行控制、事件流、结构化详情和必要的轻量产物查看。

## Proposed Changes

### 1. 产品设计文档

**文件：** `openOutCry-Agent工作室与外部接入设计建议-v0.1.md`

补充以下内容：

- 将“外部 Agent 接入”重命名为“Agent Session / Worker 接入”，明确接入对象是可运行会话，不是模型名称或聊天账号。
- 增加完整用户旅程：选择模板 → 配置实验 → 安装 Skill/发现 Runner → 本地自动接入 → 创建会话 → `/goal` 或普通指导 → 运行/审批 → 回放/报告。
- 增加 `goal_mode`、`guidance_mode`、`session_id`、`run_id`、`runner_id` 的职责边界。
- 增加 Skill、MCP Gateway、训练场协议、会话网关和 Web 事件流之间的数据流图和职责表。
- 明确普通输入、`/goal`、审批按钮、暂停/继续/中止、重试和回放的语义。
- 增加本地 Runner 的状态机、按会话启动销毁策略和本地自动授权说明。
- 增加失败状态：连接失败、心跳超时、动作解析失败、工具越权、预算耗尽、资料时点冲突和 Agent 异常退出。
- 将 Codex 设计为 Worker/App Server 适配器，避免 Web 直接仿造 Codex 聊天窗口。

### 2. 静态原型重构

**文件：** `agent-studio-prototype.html`

将现有“连接配置优先”的页面重构为三个可切换但互相连贯的界面状态：

#### A. Agent 工作室首页

- 顶部展示 Agent 列表和“新建 Agent”入口。
- 每张 Agent 卡显示：名称、来源、当前连接方式、最近会话、Runner 状态、版本、能力覆盖、评测资格。
- 新建流程先选择模板：内置研究 Agent、Codex 本地 Agent、自定义 Agent；再选择实验模板。
- 用表单配置股票池、资金、时间窗口、数据集、规则、预算、受控/探索模式和人工协作策略。
- 将协议、权限和预检放入配置流程的独立步骤，不让它们挤占主运行界面。

#### B. 会话控制台

- 左栏：当前会话和运行摘要，包括 Agent 名称、运行模式、模拟日期、净值、现金、持仓、预算、状态和控制按钮。
- 中栏：对话与事件混合时间线。用户消息、Agent 结构化状态、工具调用、证据读取、动作提案、审批、规则校验和错误使用不同视觉层级。
- 右栏：选中事件的详情，包括工具名、参数摘要、证据 ID、数据截止时间、原始动作、解析动作、规则结果和 artifact。
- 底部固定输入框：普通输入作为追加指导；`/goal` 用明显的命令提示和确认态，说明进入自动运行到底模式。
- 当前 Agent 名称固定显示在输入框附近，避免用户不清楚消息发给哪个 Agent。
- 在等待订单或高风险工具时显示批准、修改、拒绝；审批后锁定该提案，区分原始动作和最终动作。
- 在自动运行到底模式显示“仅追加指导”，不显示普通审批按钮，除非遇到阻断错误或策略规定的高风险节点。

#### C. 外部接入向导

- 首屏只问 Agent 运行位置：本地 Runner、平台托管、远程 Endpoint、官方适配器。
- 本地 Runner 路径展示 Skill 安装状态、Runner 在线状态、当前会话、运行中的 Agent 和最近心跳。
- 提供“安装 Skill”说明和复制入口，但静态原型不执行真实安装命令。
- 显示本地自动授权说明：同一机器建立本地会话，不导出长期密钥，不将凭据写入轨迹。
- 展示协议能力卡：观察接收、动作返回、工具调用、事件流、暂停恢复、artifact 和人工审批。
- 展示评测资格，但明确资格来自真实验证证据，不由 UI 的“预检按钮”直接授予。

### 3. 原型交互状态

为静态 HTML 增加只在浏览器内存中运行的演示状态：

- `agent`：当前 Agent、来源、版本和能力。
- `session`：`agent_session_id`、连接状态、当前模式和最近心跳。
- `run`：`run_id`、Goal、实验快照、状态、模拟时钟和账户摘要。
- `messages`：用户输入、Agent 摘要、工具事件、审批事件和错误事件。
- `approval`：待审批动作、原始动作、最终动作和处理状态。
- `eligibility`：严格评测、受限比较、探索运行及其证据说明。

必须演示以下主路径：

1. 选择“Codex 本地 Agent”模板。
2. 选择一个历史 A 股实验模板并确认资金、窗口、股票池和规则。
3. 点击“安装 Skill / 连接 Runner”后显示本地已接入，不启动真实进程。
4. 进入会话控制台，底部显示 `Codex · Value Researcher`。
5. 输入普通指导，追加到轨迹并保持人工审批模式。
6. 输入 `/goal 评估本窗口内的低估值机会并完成一次受控模拟运行`，显示配置已锁定并进入自动运行到底模式。
7. 展示事件流：观察 → 搜索证据 → 读取证据 → 形成结构化订单 → 等待/跳过人工审批 → 规则校验 → 结果。
8. 模拟断线或无效动作，暂停运行并展示解释、重连、重试和中止按钮。
9. 回到会话列表，能够查看会话状态和进入原轨迹回放。

### 4. 事件与消息契约示意

在协议预览中同时展示三类消息，而不是只展示 observation/action：

```json
{
  "type": "session.message",
  "session_id": "sess_demo_001",
  "run_id": "run_demo_001",
  "mode": "goal_autonomous",
  "content": "/goal 评估本窗口内的低估值机会"
}
```

```json
{
  "type": "agent.event",
  "seq": 18,
  "event": "tool.completed",
  "tool": "search_evidence",
  "summary": "返回 4 条当前时点可见资料",
  "evidence_ids": ["ev_018", "ev_024"]
}
```

```json
{
  "type": "agent.action",
  "run_id": "run_demo_001",
  "action": "order",
  "status": "proposed",
  "symbol": "ASSET_001",
  "quantity": 100,
  "requires_approval": true
}
```

协议预览中明确：MCP 工具调用、会话消息、训练场动作和平台事件不是同一种消息，不能用一个聊天文本字段替代。

### 5. 研究与实现边界

- 首版不实现完整远程 Agent 即插即用，不实现 ACP 全量兼容，不实现完整 IDE/终端嵌入。
- 首版只模拟 Skill 安装和本地 Runner 接入 UI，不在静态原型中启动 Codex、访问网络、读取用户文件或提交真实订单。
- 后续真正实现时，Runner 负责本地 Agent 进程生命周期和协议适配；Web 负责会话控制与展示；训练场后端负责规则、资料时点、账户和审计。
- Skill 负责引导 Agent 发现和使用训练场；MCP 负责研究工具；训练场协议负责 observation/action；事件协议负责前端可观测性。

## Assumptions & Decisions

- openOutCry 的核心价值是可信的 Agent 训练与评测，而不是通用 Coding Agent 聊天产品。
- `/goal` 是进入自主运行模式的显式命令；普通自然语言默认只是追加指导，不自动改变实验配置。
- 实验配置必须在运行开始前通过表单或模板确认，并生成不可变快照；Agent 不能通过聊天改写已开始运行的规则。
- 自动运行到底不等于无边界运行：越权、协议错误、预算耗尽、断线和安全阻断仍然会暂停。
- 结构化事件摘要是默认视图；原始内容和 artifact 可按需展开。
- 本地自动授权仅表示单机接入体验，不代表平台已证明外部进程可进入严格评测。
- 严格评测资格依赖真实 Runner 沙盒、网络出口、资料时点和轨迹审计证据，UI 不自行授予资格。
- 所有 HTML、Markdown 和协议示例都使用虚构 Agent、匿名标的和模拟资金，避免造成真实行情或真实连接已存在的误解。

## Verification

### 文档验证

- 检查产品规划中的 P0 能力仍全部覆盖：Agent 配置、协议、受控运行、轨迹、审批、回放和报告。
- 检查 Skill、MCP、训练场协议、会话网关、事件流和规则引擎的职责没有重叠或缺口。
- 检查严格评测、受限比较、探索运行和人机混合运行的标签及边界一致。

### HTML 原型验证

- 使用浏览器打开 `agent-studio-prototype.html`，验证首页、接入向导、会话控制台和协议预览能够切换。
- 验证普通输入与 `/goal` 显示不同模式，并且 `/goal` 不允许隐式修改实验配置。
- 验证事件流可展示 Agent 名称、工具调用、证据、动作、审批和错误暂停。
- 验证审批只处理一次，并保留原始动作与最终动作。
- 验证断线/无效动作会暂停并解释，不自动切换 Agent。
- 验证复制协议示例、移动可读布局、键盘焦点和所有模拟状态的明确标识。
- 使用桌面和窄屏视口检查事件流、输入框、审批按钮和状态标签没有重叠或溢出。

### 后端实现前的接口验收

- `session_id` 与 `run_id` 一会话一运行且全程稳定。
- 所有事件带递增 `seq` 和幂等 `event_id`，支持断线补事件。
- Runner 断线、超时、无效动作和异常退出均可恢复或明确失败。
- Agent 只能通过 MCP Gateway 使用实验允许的工具，不能直接成交或绕过规则引擎。
- 运行结束后可原轨迹回放，不重新调用外部 Agent。
