# 排版与响应式规范（design-typography）

> 适用：openOutcry Web 原型（`openoutcry-web/`）
> 生效日期：2026-10-29（第二版：字号整体上调 + 最小字号升级为全局硬约束）
> 落地位置：`src/styles/tokens.css`（令牌）、`src/styles/index.css`（`text-*` 工具类）
> 一句话原则：**字号放不下就删元素，永远不要缩字。**

---

## 0. 全局硬约束（先读这一段）

**任何可见文字，计算后的 `font-size` 不得低于 13px。** 这不是建议，是构建约束：
`npm run check:type` 会逐路由、逐文本节点测量，出现 1 处违例即退出码 1。

| # | 约束 | 数值 | 由谁保证 |
|---|---|---|---|
| C1 | **最小字号**：任何可见文字（含微标签、图表刻度、时间戳） | **≥ 13px** | `--fs-micro` 下限 13px + `check:type` 运行时断言 |
| C2 | 正文/读数类文字 | ≥ 17px | `--fs-body` |
| C3 | 说明、副行、表格注释 | ≥ 15px | `--fs-sm` |
| C4 | **不许写死 px 字号**：`text-[12px]`、`font-size: 12px` 一律驳回 | 0 处 | `check:type` 静态扫描（仅 `tokens.css` 的 clamp 允许出现 px） |
| C5 | 字号只从令牌/工具类里选：`text-micro / note / data / body / row / h2 / kpi / h1 / display` | — | 代码评审 + 静态扫描 |
| C6 | 装不下时**删元素或压 padding**，不许缩字、不许改行高凑数 | — | 密度预算（第 4 节） |
| C7 | 横向溢出 0，且 200% 缩放不丢内容 | 0px | `check:type` + `audit:ui` |

为什么会违反 C1：写死的 `text-[10px]` 会绕过 `clamp()` 的下限，于是同一个页面在
2560 宽屏和 390 手机上都是 10px——这就是 2026-10-29 之前工作室页面的状态
（212 个文本节点里 176 个 ≤ 12.5px，最小 10px）。现在这类写法在源码里已经清零。

### 怎么用（给写代码的人）

```tsx
// ❌ 一律不许
<span className="text-[10px]">交易日历受控</span>

// ✅ 微标签（13–14px，等宽大写 + 字距）
<span className="font-mono text-micro uppercase tracking-[0.1em]">交易日历受控</span>

// ✅ 说明 / 选项 / 数值（15–16px）
<span className="text-note">09:15 研究 · 09:30 起撮合</span>

// ✅ 正文 / 读数（17–18px）
<p className="text-body">选一段时间、一篮子标的、一队 Agent。</p>
```

## 1. 最小字号表（硬下限）

| 类别 | 变量 | 工具类 | 硬下限 | 用在哪 | 不许低于的理由 |
|---|---|---|---|---|---|
| 列表行主名 row | `--fs-row` | `text-row` | **21px** | 台账一行的主标题、委托单摘要句 | 行标题是一屏内最强的扫读锚点，需明显高于正文 |
| 正文 body | `--fs-body` | `text-body` | **17px** | 段落、对话正文、事件正文、指南文字 | GOV.UK 正文 19px、Material body-large 16sp、Apple 17pt，本项目取 17px 作下限；也是 iOS 输入框不触发缩放的 16px 门槛之上 |
| 数据数字 data | `--fs-data` | `text-data` | **16px** | 金额、比率、表格数值（等宽 + tabular-nums） | 数字要能逐位比对，小于 15px 时 0/8、1/7 易混 |
| 辅助说明 sm | `--fs-sm` | `text-note` | **15px** | 选项说明、表格副行、卡片注释、提示条 | CJK 在 100% 缩放下 15px 是「扫读不费力」的门槛；13px 只能算「勉强辨认」 |
| 等宽微标签 micro | `--fs-micro` | `text-micro` | **13px** | `.label`/`.chip`/`.tag`/时间戳/大写 + 字距的拉丁标签 | 大写字母 + 字距本身降低可读性，13px 是它的补偿下限，也是**全局绝对下限** |
| KPI 显示值 | `--fs-kpi` | `text-kpi` | **24px** | 账户净值、净收益等大数字 | 一级信息必须一眼可读 |
| 页面标题 h1 | `--fs-h1` | `text-h1` | **30px** | 页面主标题 | 与正文形成 ≥1.6 倍层级差 |
| 区块标题 h2 | `--fs-h2` | `text-h2` | **20px** | 卡片/区块标题、弹窗标题 | 与正文形成 ≥1.1 倍层级差且不低于 20px |
| 大标题 display | `--fs-display` | `text-display` | **40px** | 页面 hero 主句 | 只在 hero 出现一次，避免和 h1 抢位 |
| 纯装饰 | — | — | 不限 | 分隔符、印章边角、图形内无信息线条 | 不承载信息，故不受限；**任何承载信息的文字都不许低于 13px** |

### 依据（公开规范，链接已核实）

- WCAG 2.2 · 1.4.4 Resize Text（文本可放大到 200% 而不丢内容）：<https://www.w3.org/WAI/WCAG22/Understanding/resize-text>
- WCAG 2.2 · 1.4.12 Text Spacing（行高、字距、段距可调）：<https://www.w3.org/WAI/WCAG22/Understanding/text-spacing>
- WCAG 2.2 · 1.4.3 Contrast Minimum（对比度 4.5:1 / 大字 3:1）：<https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum>
- GOV.UK Design System · Type scale（正文 19px，明确拒绝“为了塞内容缩小字号”）：<https://design-system.service.gov.uk/styles/type-scale>
- GOV.UK 设计笔记 · 把排版标尺做得更可访问：<https://designnotes.blog.gov.uk/2022/12/12/making-the-gov-uk-frontend-typography-scale-more-accessible>
- iOS Safari 输入框小于 16px 会触发页面自动缩放：<https://css-tricks.com/16px-or-larger-text-prevents-ios-form-zoom/>

> 注：Apple HIG 正文基准 17pt、Material 3 body-large 16sp。本项目把 17px 定为正文**下限**、
> 18px 定为大屏上限；13px 只是「微标签」的下限，不是正文的下限。

## 2. 流体字号标尺与工具类

根字号 16px。所有级别用 `clamp(下限, 流式, 上限)`，**下限即第 1 节的硬下限**，
因此任何视口都不会跌破。令牌在 `src/styles/tokens.css`：

```css
:root {
  --fs-min:     13px;                                  /* 全局绝对下限 */
  --fs-display: clamp(40px, 1.18vw + 35.4px, 56px);
  --fs-h1:      clamp(30px, 0.52vw + 27.97px, 38px);
  --fs-h2:      clamp(20px, 0.26vw + 18.98px, 23px);
  --fs-kpi:     clamp(24px, 0.52vw + 21.97px, 32px);
  --fs-row:     clamp(21px, 0.45vw + 19.2px, 26px);
  --fs-body:    clamp(17px, 0.10vw + 16.6px, 18px);
  --fs-sm:      clamp(15px, 0.10vw + 14.6px, 16px);
  --fs-data:    clamp(16px, 0.10vw + 15.6px, 17px);
  --fs-micro:   clamp(13px, 0.10vw + 12.6px, 14px);

  --lh-body: 1.6;  --lh-sm: 1.5;  --lh-micro: 1.3;  --lh-data: 1.25;
}
```

`src/styles/index.css` 把标尺映射成 Tailwind 工具类（`@theme inline`），
TSX 里只认这九个类：

| 令牌 | 工具类 | 用途 |
|---|---|---|
| `--fs-micro` | `text-micro` | 微标签、时间戳、序号、图表刻度 |
| `--fs-sm` | `text-note` | 说明、副行、选项名、表格值 |
| `--fs-data` | `text-data` | 金额/比率（配 `font-mono tabular-nums`） |
| `--fs-body` | `text-body` | 正文、对话、字段标题 |
| `--fs-row` | `text-row` | 台账行主名、委托单摘要 |
| `--fs-h2` | `text-h2` | 区块标题、弹窗标题 |
| `--fs-kpi` | `text-kpi` | KPI 数字 |
| `--fs-h1` | `text-h1` | 页面标题 |
| `--fs-display` | `text-display` | hero 主句 |

## 3. 密度预算（回答“元素过多”）

字号定死之后，密度只能靠**删元素**解决。规则：

1. **一屏（1440×900）内独立信息块 ≤ 12**。超了就必须合并卡片或折叠。
2. **单卡数值 ≤ 6**。第 7 个开始就是噪音，改成展开区。
3. **同一屏出现 ≥3 个同类微型标签**（chip/tag/stamp），合并成一行带分隔的快照行。
4. **一屏最多 2 个主按钮**，其余收进「更多 ▾」（`<details>` 即可）。
5. **同一个事实只出现一次**：状态如果在页头说了，卡片里就不再重复。
6. 任何“为了塞下而缩小字号”的方案一律驳回——先删。

### 已执行的删减记录

| 位置 | 删前 | 删后 | 理由 |
|---|---|---|---|
| 训练场右栏 | 预算卡 + 可信度卡 + 明细卡 = 3 张 | 运行状态卡 + 明细卡 = 2 张 | 两张卡讲的是同一件事（运行是否可信），合并 |
| 运行状态卡内容 | 预算 2 条 meter + 可信度 3 行 | 预算 1 条 + 2 行（轨迹 / 协作） | 「资料时点」「研究出口」已在顶部 band 出现，卡片内删掉 |
| 训练场页头 | 运行快照 / 回放轨迹 / 暂停 / 中止 = 4 个按钮 | 回放轨迹 + 更多 ▾（内含快照/暂停/中止） | 一屏主按钮 ≤2 |
| 台账筛选 | 全部/思考/工具/订单/人工 = 5 个 chip | 全部/思考/工具与订单/人工 = 4 个 | 「工具」「订单」对用户是同一个心智：它做了操作 |
| Agent 卡 facts | 版本 / 最近会话 / 资格 / 调用预算 = 4 格 | 版本 / 调用预算 = 2 格 | 最近会话并入描述句，资格改用印章表达 |
| 顶部 band 标签 | 资料时点/研究出口/轨迹完整性/评测资格/协作方式 = 5 项 | 4 项 | 协作方式移到运行状态卡，避免同屏重复 |
| 工作室运行卡卡头 | 「当前训练 № 0042」+「3 / 20 交易日」两个元素 | 卡头只留标题，进度改成卡内「进度 3 / 20 交易日 + 进度条」 | 字号放大后卡头装不下两件事，且进度条本来就在卡里，同一事实只说一次 |

## 4. 间距、触控与行宽

- **基栅格 4px**：间距取 4/8/12/16/24/32，不出现 5、7、13 这类值。
- **段落间距** 0.75em；**卡片内距** ≥1em（当前 12–16px）。
- **点击热区**：桌面 ≥40×40px，移动 ≥44×44px（按钮视觉高 30–36px + 外扩热区）。
- **输入控件**：高度 36px，字号 ≥15px（移动端 17px，避免 iOS 自动缩放）。
- **侧栏**：`--rail` 236px —— 15px 的索引说明要能一行放下「受控历史市场 · 可审计运行」。
- **行宽**：正文 60–75ch，超过就分栏或收窄容器（当前 `.deck` 限制 54–64ch）。
- **纵向节奏**：字号放大后，靠压缩 padding 而不是缩字来维持信息量。

## 5. 断点策略

| 断点 | 现状 | 结论 |
|---|---|---|
| max-width 900 | 侧栏收起、报头精简 | 保留，属于布局断点 |
| max-width 1080 | 三栏 → 单栏、图表堆叠 | 保留 |
| max-width 1240 | 工作台三栏 → 单栏 | 保留；可改为容器查询（卡片在窄容器里就该堆叠） |
| max-height 1120 | 压缩页头与卡片内距，保证审批卡在首屏 | 保留，但**只压 padding，不压字号** |
| max-height 820 / 760 | 进一步压缩、隐藏 band 标签 | 保留；隐藏的是次要信息而非正文 |

后续可选：把卡片级布局（facts 几列、图表堆叠）改成 `@container`，与视口解耦。

## 6. 中文排版附则

- **中文不加 `letter-spacing`**（会变散）。字距只用于拉丁大写微标签（`.label`/`.chip`），取值 0.12–0.22em。
- 数字一律 `font-variant-numeric: tabular-nums`，金额用等宽栈，保证纵向对齐。
- 中英混排：中文与拉丁/数字之间留一个空格（源码里显式打，不依赖自动排版）。
- 标点用全角；括号在中文语境用（）而不是 ()。
- 标题用衬线（Georgia + Songti/SimSun），正文用系统中文（PingFang SC / Microsoft YaHei），数字用 JetBrains Mono / Cascadia / Consolas。**不联网加载字体**，保证离线可跑。

## 8. 验收标准与实测结果

### 标准

1. 六个路由 × 三个视口，**所有可见文本节点的 computed font-size ≥ 13px**；
2. 承载信息的正文 ≥ 17px，说明 ≥ 15px；
3. 200% 缩放后不出现横向滚动；
4. 控制台零报错。

## 9. 怎么执行（给后续开发者）

1. 需要字号时，**只允许**从 `text-micro/note/data/body/row/h2/kpi/h1/display` 里选，不写 px。
2. 新加一块内容前，先数一屏的信息块数量；超过 12 就先想怎么合并。
3. 想缩字号之前，先问“这块能不能删”。
4. 改完跑 `npm run check:type`（可加 `-- --shots` 顺便出截图）；
   组件层再跑一次 `npm run audit:ui`。
5. 加新控件时，先看 `src/components/ui/` 里是不是已经有令牌化的实现，别在页面里另写一套 px。
