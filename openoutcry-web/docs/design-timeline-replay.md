# 训练场：时间轴与归档回放（设计稿 v0.1）

> 2026-10-30 ｜ 状态：待讨论 ｜ 关联：`design-training-layout.md`、产品文档 §7「模拟时钟 / 决策档案 / 原轨迹回放」

## 0. 问题

现在训练场是**单一实时状态**：`RunState` 只有一份 `clock: "09:15"`、一份 `holdings`、一份 `trades`。
后果：

1. 用户看不到今天是几号、是这个训练的第几个交易日。顶栏走带有 `CLOCK 2024-04-23 09:15` 和 `SAMPLE 20 / 60 交易日`，但那是 11px 的仪器读数，不是给用户看的时间。
2. 过去的数据没有入口。切到别的任务只能看「档案」，看不到「某一天」。用户无法回答：第 2 天持仓是什么？第 3 天为什么减仓？上周三的净值是多少？
3. 没有区间概念。用户无法问：「第 5 到第 9 个交易日，这队 Agent 到底赚了还是亏了？」

一句话：**训练的载体是时间，但界面上没有时间。**

## 1. 调研：别人怎么做「回到某一天」

| 产品 | 机制 | 值得抄的 |
|---|---|---|
| **Portfolio Performance**（开源桌面） | **Time Machine**：右上角日历图标选一个日期，**所有报表**（Statement of Assets / Performance / 图表）全部按该日期渲染；默认是今天 | 时间是**全局状态**，不是某个面板的局部开关；一个控件，全页联动 |
| **TradingView Bar Replay** | 播放器式面板：`Select date…` 下拉 + 首日按钮 + 逐根前进 + 播放/暂停；图表被截断到当前回放位置 | 「逐日步进」的键盘/按钮习惯；回放时**未来被物理截断**，而不是靠灰色置灰 |
| **Fava（Beancount）** | 顶部 filter bar，时间用 `?time=2009-09` 这样的查询串；所有报表同时受筛 | 时间选择**写进 URL**：可刷新、可分享、后退键可用 |
| **Rotki** | 「P&L report」按 `start / end` 选区间，输出区间内已实现/未实现、每资产明细 | 区间不是「两天的差值」，而是**一次独立的报表** |
| **QuantConnect / Freqtrade / QuantStats** | 回测结果给一条净值曲线 + 每日收益 + 交易明细表；Freqtrade 用 `--timerange` 限定 | 每日归档表（date / equity / pnl / trades）是行业默认形态 |

结论：**三件事必须有** —— 全局时点控件、逐日步进、每日归档表；**两件事必须有但常被漏** —— 区间报表、URL 可寻址。

## 2. 设计：一个时间条，三种模式

时间选择是一个**全局状态**，放在中栏顶部，左右两栏都读它。

```
┌ 中栏顶部（sticky，56px）────────────────────────────────────────────┐
│ 2024-04-23 周二   第 3 / 20 交易日        [实时 ●]  [回放]   [最新 →] │
│ ─────────────────────────────────────────────────────────────────── │
│ ●────●────◉────○────○────○────○────○────○────○────○  20 个交易日刻度 │
└─────────────────────────────────────────────────────────────────────┘
```

三种模式：

| 模式 | 触发 | 语义 | 数据来源 |
|---|---|---|---|
| **实时** | 默认 | 「现在」那一刻 | 现有 `RunState` |
| **单日回放** | 点刻度 / 点归档行 / 改 URL `?as=2024-04-18` | 「那天收盘时」 | `DaySnapshot` |
| **区间** | 刻度上拖选 / shift 点 / `?from=..&to=..` | 「这几天累计」 | 区间聚合 |

### 2.1 时间条

- **左**：日期（衬线大字）+ 星期 + 「第 N / M 交易日」。这是用户最缺的两个数，做成页面上第二大的信息（仅次于净值）。
- **中**：刻度条。每个交易日一个刻度；有成交的点实心，无成交的空心；异常日（报错/拒单）标朱砂小点；未来日空心灰且不可点。
- **右**：模式标签（实时 / 回放）+「最新」按钮。回放时模式标签变朱砂实心，整页加一条 2px 朱砂顶线——**一眼看出不在实时**。
- **键盘**：← → 逐日步进（Bar Replay 的习惯）、Home/End 首尾、Esc 回实时。

### 2.2 回放态的无障碍与防误操作

- 中栏所有数值前加「截至」，KPI 表头加 `Stamp 快照`。
- 提案卡的动作按钮**整体替换**为一行说明：「回放模式只读。回到最新后可操作。」（不是置灰——置灰会被误认为不可用功能）
- 左栏对话**过滤到该日结束**：那天的对话就到那天为止。这是「完整回访」的一部分，否则用户会看到未来消息却看着旧持仓。
- 顶部走带的 `CLOCK` 与时间条联动，避免出现两个"现在"。

### 2.3 每日归档表

放在 KPI 带下面，可折叠，默认展开前 5 天 + 当前日：

```
日期        第N天   净值        日盈亏      成交   决策
04-23 周二   03     ¥103,762    +¥1,240     2     5     ← 当前（左侧朱砂线）
04-22 周一   02     ¥102,522    −¥310       1     3
04-19 周五   01     ¥102,832    +¥2,832     3     6
```

行 = 一天；点行进单日回放，shift 点第二行进区间。空档日（0 成交 0 决策）显示 `—` 而不是 `0`，避免看起来像坏数据。

### 2.4 区间模式

区间选中后，KPI 带整体切换为**区间报表**：

| 区间收益 | 最大回撤 | 成交笔数 | 胜率 | 换手 | 区间波动 |
|---|---|---|---|---|---|
| +2.14% | −1.36% | 11 | 54.5% | 1.8× | 0.92% |

配一条迷你净值曲线，区间部分实线、其余虚线。这是 Rotki 教我们的：区间是独立报表，不是两天的减法。

## 3. 数据模型

现有 `RunState` 是"现在"，缺"过去"。补一层归档：

```ts
/** 训练的时间骨架：交易日历 */
export interface TrainingCalendar {
  trainingId: string
  days: { date: string; index: number; weekday: string }[]  // index 从 1 开始
}

/** 每日收盘快照（不可变，追加写） */
export interface DaySnapshot {
  date: string
  index: number
  equity: number
  cash: number
  market: number
  dayPnl: number
  cumPnl: number
  holdings: Holding[]
  trades: Trade[]
  decisions: number          // 当日 agent/order 事件数
  settled: boolean           // false = 当天还没走完（进行中）
}
```

三个约束：

1. **快照是追加写、不可改**。第 3 天的快照生成后，第 5 天的操作不许回溯改写它。
2. **事件带日期**。现在 `RunEvent.at` 只有 `09:15`，必须加 `day: "2024-04-23"`，否则无法按日过滤。
3. **选择状态进 URL**：`?as=` / `?from=&to=`，与 HashRouter 兼容。刷新、分享、后退都成立。

## 4. 版面草案（桌面 1440）

```
┌ 左：对话（按日过滤） ┬ 中：工作台 ────────────────────────┬ 右：任务 ┐
│                      │ [时间条：日期 · 第N/M天 · 刻度 · 模式] │        │
│  04-23 之前的消息     │ [KPI 带（回放时 = 当日快照）]          │ 任务列表 │
│                      │ [KPI 带（区间时 = 区间报表）]          │        │
│                      │ [提案 / 账户 / 持仓]                  │        │
│                      │ [每日归档表 ▾]                        │        │
│  [插话输入 —— 回放时禁用]                                  │        │
└──────────────────────┴──────────────────────────────────────┴────────┘
```

移动端：时间条折成一行「日期 + 第N/M天 + 日期选择器」，刻度条横滑；归档表变列表；区间统计保留卡片。

## 5. 分四步做

| 阶段 | 内容 | 产出 |
|---|---|---|
| P1 数据 | `timeline.ts`：交易日历、`DaySnapshot[]` 生成（原型用确定性 mock）、事件补 `day` 字段 | 无 UI 变化，可单测 |
| P2 时间条 | 时间条组件 + 单日回放 + KPI/持仓/提案联动 + 回放只读态 | 用户第一次能"回到某天" |
| P3 归档表 | 每日归档表 + 点行跳转 + URL 同步 | 完整回访 |
| P4 区间 | 拖选刻度 + 区间报表 + 迷你曲线 | 区间统计 |

P1、P2 是主轴，P3 是入口，P4 是加分。**建议一次做完 P1–P3，P4 单独一轮。**
