### 1. 确认 Agent 工作室的功能文档与设计稿原型

Agent 工作室是产品入口，用来准备一个可以运行、可以比较的 Agent，并决定它如何进入训练场。本周把它从单一的配置页改成「配置 + 会话控制台」两段式结构，并出了可点击原型。

- **确认 Agent 来源与配置项**：来源分两类——项目自带的简单 Agent 服务，以及外部 Agent（如 Codex，经本地 Runner 接入）；配置项包括模型、提示词、研究工具、调用预算和基础风控，运行前检查连接和动作格式。每张 Agent 卡展示协议版本、最近会话和评测资格。
- **确认工作室首页**：Agent 列表 + 实验模板（股票池、资金、时间窗口、数据集、规则、预算）+ 最近会话。实验参数由表单或模板确定，运行开始后 Agent 不能改写。
- **确认会话控制台**：一会话一运行，一个 `agent_session_id` 绑定一个 `run_id`；三栏布局为运行摘要、对话与事件流、选中事件详情（工具参数、证据编号、数据截止时间、原始动作与解析动作、审批）。默认「事件流 + 审批」模式，输入 `/goal` 进入自动运行到底模式，此后只能追加带时间戳的指导。
- **明确外部接入流程**：先选择 Agent 在哪里运行（本地 Runner / 平台托管 / 远程 Endpoint / 官方适配器），再安装 Skill 并连接 Runner，完成能力发现和预检。本地接入自动授权，不导出长期密钥，凭据不写入轨迹。
- **明确接入边界**：Skill 负责发现和使用训练场；MCP 只暴露当前实验允许的研究工具；训练场协议负责 observation/action；规则引擎负责校验、拒单、撮合和账户变更。外部 Agent 只能提出动作，不能直接成交。
- **确认失败处理**：断线、心跳超时、动作解析失败、工具越权或异常退出时暂停运行并说明原因，保留账户和轨迹，不自动切换内置 Agent。

**产出**：已确认的功能文档与设计稿原型 `agent-studio-prototype.html`（含 Agent 工作室、训练场、外部接入向导、协议与 Skill、结果与复盘等页面）；接入和会话设计记录在《openOutCry Agent 工作室与外部 Agent 接入设计建议 v0.1》和《Agent 工作室与会话控制台实施计划》中。

### 2. 确认训练场的功能文档与设计稿原型

训练场是产品主体，用来让 Agent 在指定的历史时间和固定条件下进行模拟交易，并让用户看清每次决策及其结果。

- **确认一次实验的流程**：固定历史时间、股票池、资金和规则并生成不可变快照 → 提供当时可见的信息 → Agent 研究并提出订单 → 平台校验、撮合 → 更新持仓和净值 → 追加事件 → 原轨迹回放 → 复制配置重跑。
- **确认首版范围**：只做日频 A 股模拟交易，不接真实券商；订单需要检查 T+1、涨跌停、停牌、资金、持仓、交易单位和费用等规则。首版不支持的公司行为和复杂撮合场景在预检阶段阻断，不忽略后继续计算净值。
- **确认运行页面**：三栏展示，左栏是运行摘要（模拟时钟、账户净值、现金、持仓、研究预算），中栏是 AI 会话与决策时间线（观察、工具调用、证据、订单、审批、规则结果），右栏是交易与盈亏明细。会话和账户同屏，用户不需要在聊天页和交易页之间切换。
- **确认可信度与人工协作的呈现**：页面固定显示资料时点、研究出口和轨迹完整性三项状态；订单提交前提供批准 / 修改 / 拒绝，平台分别保留原始动作和最终执行动作，报告区分自主、人工确认和人机混合。
- **确认产品结构**：实验中心、模拟交易场和决策档案合并为训练场一个入口；数据与规则不单独做入口，作为实验配置、运行摘要和可信度说明的一部分出现。

**产出**：已确认的训练场功能文档与设计稿原型；《openOutcry 产品详细功能规划 v0.1》及其 HTML 阅读版，包含 MVP 信息架构、训练场能力、用户路径和运行页面原型。

### 3. 调研并设计一个简单的受控搜索工具

**要解决的问题**：Agent 回测历史交易时，不能搜索到后来才发生的新闻。因此，需要由平台统一限制搜索资料的时间，而不能只在提示词里要求 Agent 不看未来信息。

- **形成数据源选型方案**：建议使用 AShareHub 财经快讯提供结构化新闻，使用智谱 Web Search 补充中文网页报道；暂不让 Agent 直接使用通用互联网搜索。
- **确定时间规则**：训练日为 D 时，只允许返回前一自然日 23:59:59（北京时间）及之前发布的资料。例如模拟 10 月 16 日交易，最多看到 10 月 15 日结束前的资料。截止时间由服务端决定，Agent 不能修改。
- **确定最小工具设计**：对 Agent 只提供一个 `historical_search` 搜索工具，统一返回标题、发布时间、正文和证据编号；不生成 AI 摘要或买卖建议。晚于截止时间、发布时间不明的资料不返回，查询和结果留档供回放。
- **避免用返回差异泄漏未来信息**：越界查询、无结果和主题不存在三种情况返回相同的空结果，不提示「有结果但被时间过滤」。

**产出**：《openOutcry 受控搜索工具调研与设计 v0.2》。目前完成方案设计，尚未接入供应商或实现服务；账号额度、历史新闻覆盖、时间参数和正文质量仍需实测。

### 主题一·论证：记忆化问题——时点掩码、日期 / 公司匿名化、样本内外分离的必要性

学术界已系统研究「预训练见过历史行情」对金融评测的污染：

- [The Memorization Problem（arXiv:2504.14765）](https://arxiv.org/abs/2504.14765)：LLM 预训练语料天然包含宏观变量、股价时间序列与指数历史；在训练窗口内的历史数据上「预测」，输出与真实答案一致可能只是背下来的——反事实预测能力不可识别，回测表现会虚高；提示词禁止使用未来数据、日期掩码都不足以消除泄漏，唯一可行解是训练硬截断加截断后滚动评测。[QuantPedia 解读](https://quantpedia.com/the-memorization-problem-can-we-trust-llms-forecasts/)（2025-07）进一步指出：这使 LLM 历史回测的「高胜率」不可信。
- [Look-Ahead-Bench（arXiv:2601.13770）](https://arxiv.org/abs/2601.13770)：金融 LLM 前瞻偏差的标准化诊断基准，实证模型能复述具体股价与财报数字（训练数据泄漏）。

简单来说，用历史而非实时数据训练，有以下三个问题：

#### 1. Agent 可能看到未来信息

#### 2. 大模型可能记得历史

#### 3. 大模型回复基于概率和温度，一次测试结果不可靠

### 主题二·技术方案：五类抗污染手段（训练可开关变量）

承接主题一：五个手段统一做成评测内核的开关变量，默认值按场景调（教学 / 体验可放宽，排名 / 对外建议全开）；同一套内核下，开关组合本身就是实验条件，可做对照实验。实现不必从零写，上游均有可移植的开源参考（见文末链接）。

| 手段 | 做什么 | 怎么实现（开源参考） | 开关变量 |
| --- | --- | --- | --- |
| 时点掩码 | Agent 只能看到模拟时钟之前已发生的信息，未来数据不进上下文 | 在数据出口统一按模拟时钟裁剪行情 / 新闻 / 财报 / 账户视图；另配审计脚本扫描结果文件中的越界日期与真名 | `point_in_time_masking` |
| 日期 / 公司匿名化 | 切断「某年某月某股」的精确记忆检索 | 日期改成相对偏移（D±n）；代码在板块桶内做可逆置换（保留 688 / 300 / 8xx 等板块规则语义）；真名替换为「公司-XXXXXX」，并对模型输出与记忆做别名清洗。 | `anonymize_dates` / `anonymize_entities`（训练亮名、排名盲测的双模式） |
| 样本内外分离 | 尽量用所有参评模型都没见过的时段做排名 | 登记各模型训练截止时间，排名窗口取 post-cutoff 并滚动前移；更严格时对训练窗口加 purge + embargo。开源实现：ml4t/diagnostic（purged CV） | `eval_window = post_cutoff / full_history` |
| Deflated Sharpe | 修正「多试几组参数挑最好的」造成的虚高，按试验次数折算运气阈值 | 把排名指标从原始 Sharpe 换成 DSR（按试验数 K 与偏度 / 峰度折算）；开源实现：ml4t/diagnostic（PyPI ml4t-diagnostic）、pypbo，核心公式约 15 行 numpy | `ranking_metric = sharpe / dsr` |
| 最小样本量门槛 | 样本不足时不做统计判断、不进榜 | 入榜规则：不足 N 个交易日或 M 笔交易不排名。 | `ranking_min_samples`（交易日 / 交易笔数阈值） |
